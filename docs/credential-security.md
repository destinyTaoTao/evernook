# 可选凭证保管与安全设计

状态：产品设计基线确认于2026-10-29；截至2026-10-31，已有显式[加密收件箱](contracts/protected-inbox-v1.md)与[本地主口令单次显示](contracts/vault-local-v1.md)增量，未完成自动分流、完整授权/轮换/恢复闭环或正式安全验收。本页保留完整目标设计，实现范围以契约及[当前架构](current-architecture.md)为准。

## 产品职责与已确认行为

EverNook 是供 dsh、pi、桌宠等使用的外挂记忆模块。凭证保管是其中可选、独立授权的能力，不承担登录第三方系统、自动使用凭证执行任务或创建企业 IAM 的职责。

- 允许加密保存凭证；保存、读取和返回方式分别配置。
- 独立主口令在受信任本地界面输入，主口令不进入聊天、MCP 参数、环境变量、命令行或日志。
- 默认明文只在受信任本地界面展示；指定 harness 获取明文，需用户按次授权指定凭证、调用端与本次用途。
- 敏感原件加密封存，普通记忆使用脱敏投影与引用；敏感内容不参与普通抽取、embedding、摘要和上下文注入。
- 锁定时允许只能加密写入的受保护收件箱；解密仍需本地验证。加密不可用时明确失败，不落明文临时文件，也不返回完整保存成功。

## 信任与威胁范围

需要防范离线数据库/备份泄露、未经授权的本机调用、提示注入诱导取密、越权与重放、普通索引或日志意外包含凭证。调用端身份、用户解锁与本次明文授权分别验证；知道用户姓名、连接 localhost 或模型声称“用户已同意”均不足以取密。

明文返回已授权的 harness 后，后者可能将其写入会话、工具结果、模型请求与备份，EverNook 无法撤销这些副本。确认界面必须展示接收端与明文交付后果；接口返回的敏感标记不能被描述为能强制阻止宿主记录。高权限恶意程序、键盘记录器或已被控制的操作系统也超出单一应用加密能独立防住的范围。

## 安全存储与锁定写入

普通 SQLite 并不因使用本地文件就具备保险库能力。敏感值与受保护原件使用经过维护的加密实现，密钥与普通记忆数据库分开管理；不要自己设计加密算法或把解密密钥放进同一份 TOML 配置。整体数据库加密只能作为额外保护，不能替代取密授权。[OWASP 加密存储](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)、[SQLite 加密扩展说明](https://sqlite.org/see/doc/trunk/www/readme.wiki)

推荐试验“加密写入与解密读取分离”：采集路径持有接收公钥，加密原件后可靠提交；私钥由主口令保护，仅在受信任解锁流程中使用，普通记忆 Worker 不持有私钥或主口令。公钥的可信初始化、指纹核验、轮换与恢复是实施前提，不能接受模型临时提供的公钥来替换。

libsodium Sealed Boxes 等成熟机制可以只凭接收公钥加密，私钥用于解密；它本身不证明发送者身份。因此该机制只作为候选原语，调用者认证、事件身份绑定、重放限制和条目授权仍需实现并验证。[libsodium 官方说明](https://doc.libsodium.org/public-key_cryptography/sealed_boxes)

选择最终后端前需验证：加密完整性、对象与来源绑定、算法/密钥版本、锁定写入的幂等冲突检测、密钥轮换和恢复。不得公开保存低熵凭证的明文散列充当去重标记。私钥丢失且没有有效恢复材料时，密文无法被系统绕过解密；恢复材料另行加密备份并执行恢复演练。

优先评估成熟本地保险库及加密库的复用。KeePassXC 是候选，其 KDBX、GUI 解锁和 Browser API 值得验证；CLI 的明文 stdout 不能直接接到 MCP。现有 Browser API 也不直接等于通用 harness 的逐项授权。锁定写入与非浏览器交互尚未通过适配验证，当前不指定它为最终后端。[数据库操作](https://github.com/keepassxreboot/keepassxc/blob/develop/docs/topics/DatabaseOperations.adoc)、[CLI 手册](https://github.com/keepassxreboot/keepassxc/blob/develop/docs/man/keepassxc-cli.1.adoc)、[Browser API](https://github.com/keepassxreboot/keepassxc-browser/blob/develop/keepassxc-protocol.md)

## 写入与泄露闭环

1. 在普通落盘、诊断日志和模型处理之前进行敏感标记与检测，覆盖采集内容和召回问题，避免 query embedding 或查询日志漏出凭证。高敏输入允许用户或适配器直接声明为受保护原件，不能只依赖正则自动发现。
2. 开启凭证保存且加密能力可用时，原件进入受保护存储，账本记录脱敏投影、来源与受保护对象引用。两个写入步骤通过持久化收件回执与幂等关联恢复，不能出现只有投影却宣称完整保存的状态。
3. 保存开关关闭或加密失败时，仅保留符合策略的脱敏记录并明确原件未保存。未识别的凭证可能漏入普通内容，产品必须保留检测覆盖与人工标记入口，不能宣称自动识别绝无遗漏。
4. 无法检查的附件进入受保护隔离区，不进入普通索引；大小限制、格式不支持或加密失败必须显示缺口，不能静默丢弃。
5. 普通原文按 ID 读取、上下文前后扩展、缓存、导出与备份都执行同一脱敏策略。加密原件的读取和导出始终走保险库授权；普通“逐字回取”遇到受保护部分返回引用，授权后才能还原。
6. 发现历史明文遗漏时，需清理关联事实、词法/向量索引、摘要、缓存、临时文件与可控备份，并报告无法控制的宿主副本；不能只在当前界面遮住文本。

各 harness 可能先于插件保存自己的原始会话；适配器必须说明其拦截阶段。EverNook 能保证的本模块策略不能扩张为整个宿主从未记录过凭证。

本模块的取密结果如被宿主再次交回采集，应依据工具来源与敏感标记强制进入受保护路径，不依赖重新识别明文。宿主丢弃标记、复制转述或自行记录的情况仍需列明覆盖边界；流式分块可能拆开凭证格式，检测和加密暂存策略需要独立回归。

## 身份验证与明文获取

普通召回仅返回脱敏值或引用。获取明文走单独接口，不能用 `mask=false` 一类普通查询参数绕过授权。

推荐流程：已注册调用端提出指定条目请求 → 本地可信界面显示调用端、对象、字段、操作和用途 → 用户输入主口令并确认 → 签发短时、一次性且绑定本次请求的授权 → 校验未过期/未撤销后交付 → 记录无敏感值的审计事件。锁屏、超时、拒绝、撤销及重启后旧授权失效；身份验证不等于自动授予全库权限。

授权必须绑定当前凭证版本和确认内容，防止用户确认后对象被替换；并发消费必须只成功一次。请求里的用途声明用于展示和约束交付，不证明客户端事后确实只用于该目的。

解锁与交付建议由小型本地授权辅助进程承担，普通记忆核心不加载解密密钥。凭证能力关闭时不启动该进程；不用它承担普通召回，避免安全交互拖慢每轮聊天。辅助进程与 IPC 的实际隔离强度、文件权限和宿主日志行为需安全验收，不能把“不同进程”当作抵御同用户恶意程序的完整隔离。

访问控制按条目、客户端与操作收窄，审计只记对象 ID、操作、调用端、授权结果和时间。避免记录主口令、凭证、完整原文及可复原它们的错误详情。[OWASP 凭证访问控制与审计](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)

## 配置提案

以下是配置含义提案，不是已发布配置项：

| 配置 | 建议默认与规则 |
|---|---|
| 启用凭证保管 | 首次显式启用并初始化；关闭时不自动保存敏感原件 |
| 加密采集 | 独立于明文读取开关；仅在有效收件公钥与受保护写入路径就绪后启用 |
| 允许请求明文 | 建议默认关闭；开启后仍需逐次身份验证与授权 |
| 普通返回方式 | 引用或完整脱敏；禁用普通召回返回明文 |
| 明文交付对象 | 默认本地展示；指定 harness 单独准入并按次授权 |
| 期限与限制 | 解锁闲置期限、一次性授权期限、失败次数限制和重新认证条件，设置安全上限 |
| 导出与恢复 | 普通脱敏导出与加密原件备份分开；不提供定时明文导出 |

客户端不能通过一次工具调用修改安全配置或把自身加入明文准入。认证、授权、禁止凭证明文进入普通索引/日志等不作为可关闭的“性能优化”选项。

## 必要验收

- 使用合成哨兵凭证遍历原文、SQLite WAL、FTS、向量输入、摘要、缓存、审计、异常、导出与备份，检查预期路径无明文。
- 验证锁定可加密写入且不能读取；口令错误、缺私钥、错接收公钥、密文篡改与条目交换均失败，不降级为明文。
- 验证假冒用户/客户端、提示注入、过期或重放授权、撤销、并发双重消费和确认后换凭证版本均被拒绝。
- 验证加密成功后账本失败、进程强杀、重复投递、附件超限、保险库不可用及密钥轮换，恢复后原件与引用一致。
- 验证旧备份恢复时重新应用遗忘/撤销状态；凭证过期或撤销后，旧授权不能读取失效版本。
- 验证缺少凭证可选依赖或保险库锁定时，普通记忆仍可采集和召回；普通召回预算单独测量，不计用户手动解锁等待。

这些是计划中的回归与安全验证；文档核对不能证明实现已经安全。
