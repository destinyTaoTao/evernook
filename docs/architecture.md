## 选择理由

推荐独立进程的本地记忆服务，内部模块先保持简单，不拆微服务。SQLite 保存原文、重要记忆、事实版本与任务状态；FTS5 和向量索引是可重建的访问路径。Python 优先用于验证模型生态与桌宠集成，暂不锁定具体模型或框架。

先做 MemOS 本地插件复用验证，再决定使用现成内核还是自己写薄编排。复用方必须允许保留原文、控制写入确认、导出资产和验证中文召回；不满足不应为了接入而增加第二套真相源。

SQLite 的合理性来自单机单用户和事务需求，不能由此推出任意规模都快。第一版一个消息表配主体/会话/时间索引；按月分表会增加跨年查询、索引和迁移复杂度，出现实测瓶颈前不采用。

## 模块组织与交付提案

产品作为外挂记忆模块交付。建议一个仓库管理 Python 记忆核心及 TypeScript 宿主插件，发布物为一个本地运行时和按宿主分发的薄插件/MCP 入口。宿主插件安装或连接同一个运行时，不各自启动独立数据库或后台沉淀；安装、发现、版本握手和自动启动方式在 dsh 首条链路验证后固定。

以下仅为代码落地时的组织提案，当前不创建空目录或宣称已有这些包：

```text
evernook/
  pyproject.toml                 # Python 核心、CLI 与可选依赖
  src/evernook/
    memory/                      # 记忆 Interface：采集、召回、修订与沉淀
    storage/                     # SQLite、附件、迁移、持久化任务与备份
    inference/                   # 本地 embedding/抽取/重排实现
    security/                    # 调用端认证、敏感分流、策略与审计
    vault/                       # 可选凭证保管、加密收件与授权辅助程序
    transports/                  # MCP 与本地 IPC，只做协议适配
    runtime/                     # 配置、启动、调度、资源预算与健康状态
  plugins/
    dsh/                         # 原生事件采集与上下文注入
    pi/                          # 后续接入同一契约
  tests/
    contracts/                   # 插件/MCP/核心的行为契约
    recovery/                    # 崩溃、重试、迁移、备份恢复
    security/                    # 明文泄露、授权与提示注入对抗
    retrieval/                   # 中文、时间版本、近期/跨年质量
  configs/                       # 无密钥的示例配置与字段说明
  docs/                          # 需求、架构、研究、验收与 ADR
```

核心以少量稳定 Interface 提供采集、构建记忆上下文、显式记住/修订/遗忘、状态与导出；每个 Interface 包含幂等、持久化确认、权限、时间、预算和降级语义。凭证请求走独立 Interface。MCP 和本地 IPC 共用同一套检查，不能有“直连更快所以跳过授权”的分支；插件负责宿主协议转换，不重复实现事实冲突或召回策略。

采用按职责组织的模块化单体，不为每张表增加抽象仓储，也不先做通用插件框架、消息总线或多套存储。只有实际变化的本地模型、传输或凭证后端保留必要 Adapter；内部实现保持集中，避免 Interface 变成几十个可任意组合的低层调用。可选凭证辅助程序是解密能力隔离所需的专用进程，不演变成一组常驻微服务。

运行数据、保险库、密钥材料、模型与备份放在 checkout 外的可配置目录。代码与配置样例可公开；运行时安装和升级不覆盖用户数据，schema 与插件契约分别版本化，迁移前备份并验证兼容范围。

### 性能与可维护性

前台仅完成必要的安全分流、可靠写入和有界召回；抽取、embedding 构建、归纳与索引重建通过持久化任务后台处理。前台召回保留本地 query embedding 的预算，不能把普通查询依赖到整库反思上。GPU/CPU 并发和后台批次受限，防止 4070 上的大批量沉淀压住交互请求；队列积压和索引水位可查询。

SQLite 短事务与单写入调度、连接生命周期、查询取消、有界缓存及附件流式处理集中维护；用户解锁、模型推理和授权等待不占数据库事务。普通召回不依赖保险库处于解锁状态，凭证能力不可用不会把所有记忆访问拖入失败。索引一致性与缓存失效仍按事实/策略/模型版本验证，不能只靠 TTL。

### 关键配置

建议用一份带 schema 版本和类型校验的配置，包含运行时数据路径/本地接入、离线模型与资源、召回预算、沉淀计划、凭证策略、备份与可观测性等分组。公开样例只含路径和非敏感默认值；密钥、主口令与一次性授权不放入配置。

配置优先级和允许热更新的字段必须固定并记录有效版本；未知字段、矛盾组合和不安全监听范围显式报错。仅向用户暴露确有影响的开关；安全必需检查不可关闭，模型或普通客户端不能修改明文准入。关闭语义检索或周期反思允许明确降级；关闭原件保存则必须报告保存范围发生变化，不能继续返回相同的全量确认。

## 数据职责

| 数据 | 职责 | 更新原则 |
|---|---|---|
| Persona versions | 核心人设、关系边界与风格 | 用户控制版本；每次构造提示时检查预算，不能保证模型必然遵守 |
| Messages / message events | 完整原始输入与助手已生成输出 | 正常追加，保存稳定 ID、角色、来源、会话、时间与状态 |
| Important memories | 明确要求保留的完整交代 | 独立于摘要，关联原文/片段，支持指定 ID 确定性读取 |
| Facts + fact sources | 画像、偏好、事件、承诺等结构化记忆 | 来源集合、状态、发生时间/记录时间、有效区间与替代关系 |
| Summaries | 日/周/主题概括 | 只是导航与候选生成，带来源范围与生成版本，可重做 |
| Extraction jobs | 尚待沉淀的消息范围 | 同库持久化任务、租约、重试次数与处理版本 |
| Search indexes | 中文词法、实体/短词、向量访问路径 | 可从源数据重建，携带模型/分词/格式版本 |
| Protected originals + references | 含凭证的加密原件、脱敏投影与幂等关联 | 普通路径只读投影；解密、敏感原文导出与明文交付走独立授权 |

以上是逻辑职责，不要求每项一个独立服务或独立数据库。事实版本和重要记忆的需求从第一版设计，复杂图推理可后置。

### 原文与来源

保存接收时的原始文本，不做 Unicode 归一化覆盖；检索归一化使用独立派生字段。明确字符偏移采用何种计数方式，中文、emoji、换行和组合字符均需往返测试。为消息保存内容哈希，用于发现非预期变化；单独存一个哈希不等于防篡改或备份。

含凭证的原件在普通落盘前转入受保护路径，保留授权后逐字还原能力，日常来源回取使用脱敏投影。敏感原件不公开保存明文散列；来源范围需要区分原件和投影坐标，来源校验在对应数据版本上进行，不能把脱敏偏移当作原文偏移。

事实可由多条消息共同支持，因此需要多对多来源关系，不能只有一个 source_message_id。来源片段必须与原文核对；LLM 给出的置信分数不是事实真伪证明。

区分事件发生时间、服务接收时间、系统得知时间和事实有效时间。接收时间统一保存 UTC，显示/自然语言日期按明确的用户时间区解释；导入旧记录不能用导入日期冒充事件日期。

### 重要记忆

显式“记住这段话”应同步写入原文引用和重要标记，不等待日终抽取。将重要记忆分为有限的每轮必读集合与按主题召回集合；后一种仍可按 ID 无损读取。集合过大时必须报告预算冲突，不能偷偷截断再宣称全部记住。

精确回忆请求返回原文；如果超过单次响应预算，分页返回并显式标明范围与剩余内容。摘要只作为附加解释，不能冒充逐字引用。

受保护部分不通过普通回忆接口返回明文，按 ID 读取也不能绕过；需要完整敏感原话时启动保险库授权流程。

## 每轮写入

1. 宿主插件产生稳定的请求幂等键。先做敏感检测/分流；普通原件或脱敏投影、受保护对象回执、重要标记和待处理任务按持久化契约提交后，再返回对应保存确认。
2. 构造召回与模型上下文。数据库事务不跨 LLM/API 网络调用。
3. 助手输出关联输入消息，并保留尝试、分块与完成状态。已确认要求是显示过的片段必须可恢复，不能以仅保存最终结果替代显示前持久化；当前固定内核探针只证明落点可行，实际展示通道和恢复回放仍待 T10 验收。
4. 后台任务读取尚未处理的普通消息/脱敏投影范围，调用抽取器生成候选，在库外完成耗时推理；不解密敏感原件。
5. 短事务内校验来源、写入派生事实/索引状态，并将任务标记成功。提交成功后才推进处理水位；任务重跑按消息范围与抽取版本幂等。

若抽取或 embedding 失败，原文仍可按 ID、时间和已完成的词法路径读取。若原文提交失败，调用方必须得到失败；允许用户决定是否继续无持久化对话，不可假装已经保存。

后台 Worker 初版保持一个写入调度点；需要多 Worker 时再加入有到期时间的任务租约。并发事实更新使用预期版本检查，不能以最后一次写入无条件覆盖用户更正。

SQLite WAL 可改善读写并发，但仍要控制写事务与忙重试；数据库必须在受支持的本地文件系统上。断电持久性需要明确 synchronous 策略并验证；不能以启用 WAL 代替持久性设计。[SQLite WAL](https://www.sqlite.org/wal.html)

## 每轮召回

先做主体、可见范围与历史时点过滤，明确当前问题是在问“现在”还是“当时”。检索不触发整库 LLM 扫描。

1. **确定性路径**：消息 ID、重要条目 ID、明确原话/实体与日期范围；支持完整原文回取。
2. **中文词法路径**：使用成熟中文分词方案生成独立索引列，并验证短词、专名、数字与英文混排。FTS5 unicode61 不等于中文分词；内置 trigram 只作为对照候选，三字符以下的查询必须有明确路径。查询字符串需要转义/构造，不能直接把用户输入当 FTS 语法。
3. **语义路径**：按问题和必要的近期指代上下文生成 query embedding，检索带来源的记忆片段与事实；不依赖语义相似度单独完成冲突判断。
4. **最近七天路径**：在滚动七天范围内做相关检索，分配独立候选配额；全历史路径始终保留。不把七天原文全部塞进上下文。
5. 候选按稳定来源去重，RRF 是初始融合基线；在相关性与时间有效性通过后给近因有限加权。询问历史时点时不能被当前状态覆盖。
6. 回取命中原文及必要的前后消息，完成 token 预算、来源标注与矛盾提示；无来源则输出证据不足。

每轮必读的人设、未完成承诺和有限重要集合有单独预算。它们影响行为上下文，但不是任意问题的标准答案，也不能让过期偏好覆盖新的明确指令。

### 最近七天更快的具体含义

- 时间索引限制近期候选集合，保留独立近期召回额度。
- 近期已处理片段与查询向量可采用有界缓存，键包含主体、索引/模型版本、时间窗和事实版本；更正/删除后失效。
- 时间衰减在相关候选内部使用，不能让昨天的无关聊天压过三年前的精确答案。
- 按近期与全历史分别报告 Recall@k 和 p95；只有真实测量才能证明近期更快。

不在首版引入冷热数据库分离；“七天热区”首先是查询策略，是否需要额外物化表由实测决定。

## 更正与自我沉淀

候选状态至少区分待确认、当前有效、已替代、已撤销和有争议。“下个月搬家”是未来计划，不应立即使当前住址失效；“刚才说错了”是纠错，也不一定产生现实世界的一段旧有效期。

自动任务可生成事实候选、日/周摘要、重复项建议；清晰且有来源的非冲突事实可自动接纳。冲突、身份混淆和重大人格变更需要确认。原文、旧版本和更正理由用于审查回滚。摘要递归生成时仍需追溯到原始消息，不能只引用另一个摘要。

禁止把历史文本中的指令提升为 system 权限。检索到的消息/网页/引用只是数据；工具执行与权限决策由桌宠运行时控制，不能由记忆中的一句话授权。

## 模型与索引迁移

embedding 记录模型标识、revision、维度、距离/归一化方式和分块版本。不同空间的向量不可混搜。新索引并行构建、校验完成后切换，保留旧索引直到可回滚；查询缓存同时换代。

选择 sqlite-vec 前验证当前 Windows/Python 版本是否能加载扩展，核对扩展版本和查询限制。其使用便捷不代表某一数据规模的端到端时延已经达标。[sqlite-vec](https://alexgarcia.xyz/sqlite-vec/)、[KNN 文档](https://alexgarcia.xyz/sqlite-vec/features/knn.html)

FTS5 external-content 表需要触发器、同事务应用写入或受控重建来同步。必须覆盖新增、更正、删除和恢复重建的索引一致性检查。[SQLite FTS5](https://www.sqlite.org/fts5.html#external_content_tables)

## 多年保存与恢复

粗略容量示例：每天 500 条消息、每条原文 1 KiB，五年约 91 万条、0.9 GB 原文；这是算术假设，不包含元数据、索引、向量和备份。10 万条 1024 维 float32 向量本体约 0.41 GB，实际数据库还会增加结构开销。GB 级不是固定结论，更不能据此保证时延。

数据库与附件保存在代码仓库外；提供版本化 JSONL 导出、来源映射、格式说明和快照清单。WAL 模式下不要只随手复制正在写入的主 db 文件；使用 SQLite 一致性备份能力，执行异盘备份、完整性检查与实际恢复演练。[SQLite Backup API](https://www.sqlite.org/backup.html)

普通导出只包含允许导出的原文与脱敏投影，敏感原件以加密包保管；密钥恢复材料单独加密备份。不得将敏感原件自动解密拼入 JSONL；恢复演练需覆盖账本、受保护对象、关联回执与撤销清单的一致性。

备份频率、保留与目标已由 [R1 契约](contracts/r1-memory-v1.md)记录；实际独立目的地、恢复材料、启用及恢复验收继续待办。当前[普通归档与审查恢复](contracts/archive-v1.md)不承担加密备份或运行时恢复。检测磁盘空间、备份失败和任务积压；明确区分本机崩溃恢复与设备丢失恢复。用户要求删除时应阻断召回并清理派生资产，备份中的残留及过期策略须透明说明；永久删除属于另行确认的操作。

## 可观测性与降级

只记录 ID、耗时、命中类型、任务失败码和水位等必要指标，默认不把私人原文写到诊断日志。分别测量 query embedding、词法/向量查询、融合回源、重排和生成。

向量不可用时退回词法/时间/精确查询，返回降级标记；索引落后时返回水位，不能把“没有索引到”误说成“从未发生”。若必须完整历史检索，应允许等待追平或明确告知当前边界。
