# Vault recovery workspace cleanup implementation plan

**Goal:** 在恢复和接回写入临时副本前登记可认证工作区，并提供可信管理员显式清理。

**Architecture:** 账本私有目录内的签名登记绑定工作区绝对路径、类型和 NTFS 目录身份；工作区仍在目标卷，保证原有原子发布。创建空私有目录后、写入任何敏感材料前落盘登记。停服务并持独占栅栏时，仅清理登记认证、目录身份与内容白名单均匹配且不含 reparse point 的工作区；未登记旧目录、已发布容器和独立备份不做自动删除。

**Constraints:** Windows/NTFS；无模型工具；管理员凭据与本地权限；不承诺物理安全擦除或旧版本未知残留的发现；保持日用门禁。

1. 新增 workspace 受控上下文、认证登记、完整性校验与幂等清理；覆盖登记前后崩溃、损坏、替换、重解析点、非预期文件与清理失败。
2. 将 restore/attach 临时目录改为受控上下文，保留原锁顺序与跨卷限制；用真实子进程复测发布及接回前后崩溃。
3. 新增可信本地 SDK／CLI 清点和显式清理接口；覆盖权限、运行中服务、并发和未登记残留保护。
4. 对相关源码及非 editable wheel 运行回归、类型检查和独立安全审查；记录遗留销毁、备份与物理擦除限制，再提交推送并更新票据。
