# 已恢复保险库安全接回（#215）

1. 停止独立服务并取得服务锁、账本独占栅栏，重新核对管理员、恢复回执与缺失保险库状态。
2. 在隔离账本副本上重新验证暂存保险库的口令、材料、全部签名/原文及当前普通关联；不把 #214 的历史暂存结果当作授权。
3. 在同一个 SQLite 事务中将缺失标记切换为受账本密钥认证、绑定恢复回执与具体收件箱/密钥目录的接回标记。失败或崩溃时仅存在缺失或已接回状态，不开放未认证的中间态。
4. 服务启动和保险库访问复核接回标记、目录绑定与关键材料，缺失或不一致时拒绝启动/访问；不能回退为旧版共享写入。允许安全重试，不自动改变普通记忆的抑制或画像准入。
5. 使用隔离合成数据覆盖成功、错误口令、材料和关联篡改、旧暂存、权限、并发、提交前后崩溃与重启；安装包回归、类型检查和独立安全审查通过后提交。独立设备仍可能持有旧副本，不能声称阻止其离线分叉或清除额外备份。
