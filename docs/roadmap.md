# 路线与验收

本文件保留目标路线与验收门槛，基线日期：2026-10-29；当前实施状态更新：2026-10-30，见[当前实现与架构图](current-architecture.md)。R1 已有主要本地能力，R3 已有词法/精确路径；各阶段尚未全部验收，以下性能与质量指标仍为待测目标。

## R0：选型与复用验证

以同一套合成中文场景比较最小自建方案与 MemOS 本地插件；Mem0 作为必要时的第三个对照。确认依赖、原文留存、写入确认、版本/删除语义、Windows 接入、导出和许可。不要为了比较搭建所有框架。

产出：采用或不采用的短 ADR、最小调用链、测量配置、桌宠接入契约。只有测量才能判断自建的维护成本是否值得。

## R1：可恢复原文与重要交代

消息幂等写入、显式重要标记、按 ID/时间查原文、原文导出、备份恢复、任务持久化。先证明数据不会因摘要或模型失败丢失，预留事实时间与版本字段。

验收：重启和恢复后原文逐字一致；重复请求不重复存储；相同幂等键不同内容被拒绝；磁盘满/忙锁不返回假成功；重要标记不依赖后台抽取完成。

## R2：事实抽取与更正

来源校验、候选状态、版本更新、历史时点查询、后台中断重跑、审查与撤销。Persona 明确由用户管理。准备更正与反例测试后再接真实私有数据。

验收：否定、转述、助手幻觉、角色扮演不会悄悄变成用户现实事实；过去/现在/计划能够区分；Worker 重跑不重复创建事实，冲突不会静默覆盖。

## R3：中文混合召回与七天热记忆

验证中文词法与短词策略、embedding 与 sqlite-vec 候选，增加来源片段回取、RRF 基线、历史时间过滤与近期独立配额。由实测决定是否增加重排模型或物化热区。

验收：近期相关候选优先且保留旧重要事实；索引滞后/不可用时正确降级；缓存不复活已撤销事实；更换 embedding 时新旧空间隔离。

## R4：桌宠适配与长期运行

只接一个已确认外壳，验证多轮指代、上下文预算、流式失败、断网、备份告警、用户纠错/遗忘界面。连续运行观察与恢复演练通过后，才考虑关系图、多模态和更多适配器。

## 正确率门槛草案

以下是**拟议目标**，不是当前成绩，也不是对任意问题的保证。正式实现前冻结测试集和计分方法；不同模型选择不得只挑有利样例。

| 指标 | 初始目标 | 测量边界 |
|---|---|---|
| 重要原文按 ID 回取 | 100% 逐字一致 | 已确认提交的测试数据，含标点、数字、换行、emoji；另测恢复 |
| 消息幂等 | 100% 符合契约 | 并发重复、客户端重试与键冲突 |
| 关键证据 Recall@10 | ≥95% | 人工标注中文查询集，近期/跨年/短词分组单报 |
| 当前/历史事实选择 | ≥95% | 明确时间与纠错标签；含未来计划、同名主体 |
| 无答案场景 | 虚构事实为 0 | 固定对抗集，每次发生都作为回归；不推断开放世界为零风险 |
| 事实来源有效 | 100% 引用可解析 | 来源存在、片段匹配、未越权、未被删除 |

至少准备 200 条人工核对的查询，覆盖五年时间跨度、20 组更正/冲突、短中文名词、否定、未完成承诺、多轮代词、导入旧消息、角色扮演与提示注入。先用合成数据；真实数据只在用户明确同意的本地环境使用，不上传仓库。

检索与最终回答分别打分。证据已命中但模型答错，不能算检索失败；只返回“没有找到”虽然避免编造，也不能算问答成功。

## 性能目标草案

- 两档目标数据：10 万与 100 万消息；向量记忆数量单独记录，不将全部消息数冒充向量数。
- 初始观察目标：暖缓存本地候选检索、融合与回源 p95 ≤150 ms；最近七天词法/时间路径 p95 ≤50 ms。需在目标机器校准，未达标时先查瓶颈。
- 另报 query embedding、重排、网络 API 和生成耗时；完整召回请求的 p95 是这些实际耗时的整体测量，不能用数据库耗时替代。全链路目标待本地/云模型选型后确定。
- 分开报告冷启动/暖缓存、近期/全历史、无答案/热门查询、有写入/无写入、索引正在重建/正常状态，以及 p50/p95、样本数、错误率、峰值内存和磁盘体积。
- 记录 CPU、内存、磁盘、OS、Python/SQLite/扩展版本、模型 revision、维度、分块策略、数据集哈希和配置，才能复现。

不预先承诺“百万消息总链路毫秒级”“几年数据几分钟重嵌入”或按代码行数推算可生产交付时间。先完成 R0/R1 的真实验证，再估后续工期。

## 故障与对抗场景

1. 用户消息提交后模型超时或进程退出，仍可回查输入。
2. 原文落库后、抽取前崩溃；任务可恢复，不漏水位。
3. 抽取生成后、事务提交前中断；重试无重复事实。
4. FTS/向量失败、数据库忙、磁盘满；状态透明，不假成功。
5. 用户更正和后台旧任务并发；旧任务不能覆盖新确认。
6. 更换 embedding、分词版本或 schema 后恢复/回滚；证据链完整。
7. 备份恢复到新目录；原文、来源与重要记忆一致，派生索引可重建。
8. 用户要求遗忘后，检索、缓存和摘要不能继续暴露目标；说明备份保留边界。
9. 近七天有大量无关消息，仍能命中几年前的精确承诺。
10. 历史消息含“忽略系统指令”等文本，不能影响权限或核心人设。
