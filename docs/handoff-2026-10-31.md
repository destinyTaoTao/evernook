## 需要在新机器重建的环境

代码固定 Python `>=3.14,<3.15`，开发验证为3.14.4 / SQLite3.50.4；Node要求24.x且不低于24.11.0，验证为24.11.1。MCP2.3.0、PyNaCl1.6.2、mypy1.18.2由pyproject固定。Python安装示例：

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m mypy src
```

如需重跑全部契约测试，可用 `python -m unittest discover -s tests/contracts -v`；这不是本次已执行的全量命令。较小验证优先使用本票据的测试文件。

原生适配开发：

```powershell
$env:EVERNOOK_TEST_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
$env:EVERNOOK_TEST_OUTPUT = Join-Path $env:TEMP 'evernook-synthetic-harness-tests'
Set-Location plugins/harnesses
npm ci --ignore-scripts
npm run typecheck
npm run build
npm test
```

插件锁定pi-coding-agent/pi-ai1.4.0、dsh0.2.1-rc.3、Cordis4.0.5，依赖版本见package-lock。测试环境变量指向仓库外的合成数据目录，测试使用确定性provider，不需要私人模型API key。所有配置和进程入口都不应硬编码原电脑的绝对路径。

**不在Git里的内容：**虚拟环境、node_modules、模型权重/缓存、私有运行库、访问令牌、保险库密钥/主口令、密文原件与备份、一次性日志都保留在仓库外或被忽略。GitHub能完整恢复源码/规格/实施进度，不能据此恢复旧机器的私人记忆和密钥。家里电脑应新建合成运行目录、配对身份；迁移真正私有资产需独立安全传输，绝不将其提交公共仓库。

本地MiniLM/Qwen不自动下载模型。原电脑已有固定资产，配置按契约的模型/worker/prompt散列检查；新机器需重新准备符合这些身份的资产及显式仓库外配置，参见[语义](contracts/semantic-v1.md)、[抽取](contracts/extraction-v1.md)和probes说明。原电脑一次实际Qwen运行成功21.001秒不等于质量准入，MiniLM一次耗时亦非p95承诺。
