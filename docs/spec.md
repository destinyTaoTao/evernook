# EverNook：离线、可追溯的跨入口长期记忆

状态：Spec 与测试边界已由用户确认。设计基线与测试边界确认日期：2026-10-29。

已发布：[GitHub Issue #1](https://github.com/destinyTaoTao/evernook/issues/1)，标签：`ready-for-agent`。

这是完整产品的分阶段规格，不代表功能已经实现。首个可执行阶段为 R0；后续阶段必须通过各自准入条件，不能把待验证选型或待确认参数默认为已经批准。

## Problem Statement

用户在 dsh、pi、桌宠等入口与同一个 AI 长期交流，切换入口、跨会话或压缩上下文后，共同经历、重要交代与做事经验容易丢失。仅保存摘要不能逐字回取原话，仅做语义检索也不能保证找到正确的历史事实。原始记录、事实更正、索引和备份若缺少一致语义，还可能导致重复记忆、旧事实覆盖新更正，或遗忘内容在重建后复活。

用户需要自己持有、能够迁移和恢复的长期记忆资产，同时希望最近七天更容易想起、跨年重要信息仍能找到。含凭证内容需要与普通记忆分离，不能因跨入口共享或模型请求而暴露明文。

## Solution

提供一个独立、本地运行的外挂记忆模块，先接入 dsh，再接 pi 和一个确认的桌宠外壳。同一 AI 的已授权入口共享一份权威证据账本；项目和入口作为来源与相关性信息，不默认构成隔离墙。

原始证据先可靠提交，再形成可重建的情景、事实、经验和导航摘要。显式重要交代具有独立于抽取模型的确定性回取路径。召回返回来源、时间、事实状态、处理水位与降级信息；普通召回新增等待约 1 秒是待测目标，复杂追忆使用单独预算。

存储、embedding、抽取、重排与沉淀全部离线，不自动转云端。EverNook 不内置聊天，调用端自行负责收到证据后的模型调用、数据出机及工具权限。

凭证保管为可选能力：敏感原件加密封存，普通记忆仅使用脱敏投影；锁定时可加密写入，解密需要本地独立主口令验证，交给指定 harness 还需要本次授权。

## User Stories

1. As a 用户, I want 在不同交流入口延续同一个 AI 的记忆, so that 切换工具不必重复讲述背景。
2. As a 用户, I want 保存入口实际提供的用户和助手原文, so that 多年后仍能回查共同经历。
3. As a 用户, I want 保存工具调用、结果、附件与来源, so that 结论可以回到当时的证据。
4. As a 用户, I want 获知未采集、未完成或未保存的范围, so that 不把不完整档案误认为全量记忆。
5. As a 用户, I want 只有可靠持久化后才收到保存确认, so that 不因异步任务或进程退出丢失已确认内容。
6. As a 调用端开发者, I want 重试同一源事件得到一致回执, so that 重连不会重复创建消息与任务。
7. As a 调用端开发者, I want 相同幂等键但内容不同被明确拒绝, so that 来源冲突不会静默覆盖证据。
8. As a 用户, I want 明确要求记住的原话立即生效, so that 不必等待后台模型提炼。
9. As a 用户, I want 按指定条目逐字回取重要交代, so that 数字、标点和原意不会被摘要替换。
10. As a 用户, I want 超长原话分段返回并标注剩余范围, so that 内容不会被静默截断。
11. As a 用户, I want 核心设定与有限的必读内容有明确预算, so that 超出上下文容量时得到真实提示。
12. As a 用户, I want 用中文短词、专名、数字和语义查询记忆, so that 表述变化时仍有机会找到正确证据。
13. As a 用户, I want 最近七天有独立召回额度, so that 近期事情容易想起。
14. As a 用户, I want 全历史检索始终保留, so that 无关的新消息不挤掉几年前的重要承诺。
15. As a 用户, I want 区分当前状态与历史时点, so that 问当时的事情不会只得到现在的答案。
16. As a 用户, I want 导入旧记录仍保留实际事件时间, so that 导入日期不会污染经历顺序。
17. As a 用户, I want 事实和摘要附带可解析的原始来源, so that 可以核对记忆是否有据。
18. As a 用户, I want 助手生成、第三方引用和角色扮演分别标识, so that 它们不会被学成我的现实事实。
19. As a 用户, I want 区分说错后的纠正与现实情况变化, so that 历史不会被错误解释。
20. As a 用户, I want 明确更正立即影响后续读取, so that 后台旧任务不能覆盖新确认。
21. As a 用户, I want 含糊或冲突内容保留争议并请求澄清, so that 系统不会替我选择事实。
22. As a 用户, I want 有来源且无歧义的信息自动沉淀, so that 不需要每次手工整理。
23. As a 用户, I want 从经历总结可追溯的经验, so that AI 能延续有效方法与失败教训。
24. As a 用户, I want 核心人设、关系边界和执行规则由我确认, so that 自动沉淀不会获得新的行为权限。
25. As a 用户, I want “忘记”默认阻止再次召回但保留原档, so that 能控制回答而不误删证据。
26. As a 用户, I want 明确申请彻底删除并看到备份残留边界, so that 不把界面隐藏误认为所有副本已销毁。
27. As a 用户, I want 重建索引和恢复备份仍应用更正与遗忘限制, so that 旧内容不会复活。
28. As a 用户, I want 模型或索引不可用时仍能使用可用证据路径, so that 一项依赖失败不会让原文不可访问。
29. As a 用户, I want 超时、无答案与索引滞后分别说明, so that 不把暂时找不到误认为从未发生。
30. As a 用户, I want 后台沉淀可暂停、可恢复且受资源预算约束, so that 不持续拖慢前台交流。
31. As a 用户, I want 睡眠或关机错过的维护任务合并补跑, so that 不产生无意义的重复任务。
32. As a 用户, I want 在断网状态完成记忆处理, so that 不会因静默云端回退泄露数据。
33. As a 用户, I want 版本化导出、备份与实际恢复验证, so that 更换机器或组件不丢失记忆资产。
34. As a 用户, I want 运行数据、模型、备份与密钥留在源码仓库之外, so that 公开代码不带出私人记录。
35. As a 用户, I want 可选加密保留含凭证的原件, so that 有授权时仍能还原完整内容。
36. As a 用户, I want 普通检索、摘要和日志只处理脱敏投影, so that 共享记忆不等于共享凭证明文。
37. As a 用户, I want 保险库锁定时仍可加密收件, so that 保存不要求长期持有解密能力。
38. As a 用户, I want 加密不可用时明确失败且不回退明文, so that 失败路径不降低安全边界。
39. As a 用户, I want 在受信任本地界面输入独立主口令, so that 口令不进入聊天、工具参数或日志。
40. As a 用户, I want 默认仅在本地展示凭证明文, so that 不自动把凭证交给模型或宿主。
41. As a 用户, I want 按凭证版本、调用端、操作和用途逐次授权交付, so that 一次确认不变成全库许可。
42. As a 用户, I want 拒绝过期、撤销、重放和并发重复消费授权, so that 旧许可不能再次取得明文。
43. As a 用户, I want 明确宿主保存或外发明文的边界, so that 知道模块无法撤销哪些外部副本。
44. As a 调用端开发者, I want 原生插件与 MCP 使用相同记忆规则, so that 传输方式不会改变权限和一致性。
45. As a 维护者, I want 使用同一套合成中文场景比较复用与最小自建方案, so that 选型依据来自可复核证据。
46. As a 维护者, I want 分别报告保存正确性、证据召回与回答忠实度, so that 不用某一环成功掩盖其他失败。

## Implementation Decisions

### 已确认的不变量与边界

- 单用户、本机服务；一个权威证据账本，派生记忆与索引可追溯、可重建。分类、去重和摘要不能改写唯一原文。
- 普通文本保留接收时原样内容；检索归一化使用派生表示。来源保留入口、会话、分支、角色、顺序、事件时间、接收时间与完成状态。
- 稳定来源身份用于幂等，不按文本相同就合并两次真实发生的交流；内容冲突不得静默接受。
- 显式记住、用户指定目标的更正与抑制需要可靠提交并立即影响后续操作，不能等待向量或抽取完成。
- 多来源事实保留来源集合、状态、发生/得知/有效时间及替代关系。明确纠错、现实变化、未来计划分别处理；歧义不由最后写入者胜出。
- 耗时推理不占数据库事务；任务状态与成功水位一致提交。重跑幂等，后台旧结果不得覆盖新更正或绕过遗忘限制。
- 原始证据与取回文档均为不可信数据，不授予工具权限，不提升为高优先级指令。
- 重要原话支持指定条目确定性回取；普通接口遇受保护部分只能返回投影或引用。原件与投影各自使用明确版本和坐标。
- 先执行有效性、权限和遗忘过滤，再构造候选与上下文；缓存、摘要、索引重建和恢复均遵守相同限制。
- “不再召回”与“彻底删除”分离。恢复旧快照必须核对之后的抑制、撤销和删除记录，记录不完整时先审查，不直接宣称遗忘状态完整。
- 所有记忆处理离线；依赖失败不自动云端回退。聊天模型、工具执行和证据交付后的出机由调用端负责。
- 记忆服务不因模型自称获准或 localhost 连接而认可身份。凭证明文接口与普通召回分离，解锁、调用端认证和逐次授权分别校验。
- 授权绑定当前凭证版本及确认内容，短时、一次性；并发消费只成功一次。拒绝、过期、撤销、锁屏及重启后的旧授权不得交付明文。
- 主口令不进入聊天、MCP 参数、环境变量、命令行或日志。普通 Worker 不持有解密私钥，安全必需检查不可由普通客户端关闭。
- 加密写入、普通账本关联与回执必须可恢复；仅投影保存与原件完整保存返回不同状态。不可检查附件不得进入普通索引。
- 未识别凭证仍可能漏检，需人工标记与历史副本治理入口；不能把合成测试通过描述为现实世界零泄露保证。

### 待 R0 验证的技术提案

- 采用模块化单体，建议 Python + SQLite，宿主薄插件与 MCP 连接同一本地运行时；不先拆微服务或增加第二套真相源。
- 核心职责为采集、上下文构建、显式记住/修订/遗忘、状态与导出；模型、传输和可选凭证后端仅保留实际需要的适配边界。
- 中文词法、精确路径、本地语义与滚动七天候选共同召回；RRF 为融合基线，必要时按剩余预算重排。具体组件与模型不是已冻结选型。
- 小型本地授权辅助程序隔离凭证交互和解密能力；成熟保险库或加密库优先复用。进程分离不等于能抵御同用户恶意软件。
- 少量必要配置覆盖数据路径、离线模型、资源、召回、沉淀、凭证和备份；必须有版本与类型校验，密钥不放公开配置。

### 分阶段执行与准入

| 阶段 | 交付与准入条件 |
|---|---|
| R0：复用与接入验证 | 首先执行。用同一套合成数据比较 MemOS 本地插件与最小自建路径，不为比较搭全套框架；固定被测版本、依赖与许可。产出 dsh 最小真实链路、采集能力/缺口矩阵、离线验证、中文检索与时延报告、采用或不采用的短 ADR。验证凭证候选的锁定写入、独立解锁、按次授权和恢复，未通过则不启用可选凭证能力。 |
| R1：可靠底座 | 在确认内核、目标平台、可靠采集与敏感分流方案后实施。交付幂等原文、重要交代、显式更正/抑制、持久化任务、导出和恢复。冻结字符位置与流式未完成记录契约；备份策略及可接受丢失/恢复窗口在相关能力实施前确认。 |
| R2：事实与更正 | 在来源和时间契约明确后实现自动抽取、候选/争议状态、纠错与现实变化区分；回归先于接入真实私人数据。 |
| R3：召回与沉淀 | 在模型、数据集、计分和预算明确后实现多路召回、七天视图、日/周维护与恢复补跑。冻结用户时间区、必读集合预算、普通/深入查询边界及最终性能门槛；未达标报告限制，不删掉全历史路径。 |
| R4：跨入口与长期运行 | 在已验证的 dsh 链路上先接 pi，再接一个确认的桌宠；各入口实施前明确版本、捕获阶段、补齐与注入能力。验收共享、分支、长期运行与恢复。 |

R0 允许原型与验证代码，不等于启动全部生产实现。若无法满足已确认产品不变量，应记录失败证据、提出最小替代方案；不得静默降低保存、安全或共享语义。需要用户决定的门槛与产品取舍保持待确认状态，在依赖阶段停止推进。

## Testing Decisions

测试只验证外部可见行为和已确认契约，不断言内部表结构、类拆分或特定算法调用次数。当前仓库没有可复用的运行实现或测试套件；已有需求、路线和安全场景是验收依据，以下测试边界已由用户确认，测试本身尚未实现或运行。

- **主边界：统一记忆外部契约。** 覆盖采集、持久化回执、重要标记、按 ID/时间回取、召回、更正/抑制、导出与重启/恢复；原生插件与 MCP 复用同一组行为断言，避免每个内部模块重复造测试入口。
- **宿主集成：最小真实 dsh 链路。** 验证采集发生阶段、模型调用前提交、自动注入、源事件身份、分支、流式中断、重试及重扫补齐；不能以核心 mock 测试替代宿主覆盖证明。
- **独立安全边界：凭证申请与授权交付。** 验证锁定写入、本地验证、对象/版本/调用端绑定、并发一次性消费、撤销与错误密钥等；不并入普通召回接口。
- 恢复测试在外部提交/确认的不同窗口中断进程，重启后核对原文、任务、受保护对象及回执；注入磁盘满、忙锁和依赖失败，确认没有假成功。
- 更正/抑制与后台旧任务并发、重复投递、索引重建及旧备份恢复必须有有意义的回归；未解决恢复后的撤销边界不得开放正常召回。
- 使用合成哨兵凭证检查普通账本、WAL、索引输入、摘要、缓存、日志、异常、普通导出和备份的预期路径；另测敏感取密结果回流与流式分块。
- 中文合成集覆盖跨年、近期竞争、一字/两字词、专名、否定、未来计划、同名主体、引用、角色扮演、无答案和提示注入。质量验收前冻结至少 200 条人工核对查询，含至少 20 组更正/冲突。
- 保存正确性、检索命中和最终回答忠实度分别计分；没有聊天功能的服务不承担调用端生成模型的正确性保证。

| 指标 | 现有拟议目标与边界 |
|---|---|
| 指定重要原文回取 | 已确认提交的测试数据 100% 逐字一致，含换行、标点、数字、emoji 及恢复；受保护内容通过授权路径验收 |
| 幂等、来源 | 固定契约集 100% 符合；来源可解析、片段匹配、无越权、无已删除来源 |
| Recall@10、当前/历史选择 | 各拟议 ≥95%，近期/跨年/短词分组报告；最终数据集与门槛在依赖阶段冻结 |
| 无答案 | 固定对抗集虚构事实为 0；不推广为开放世界零风险承诺 |
| 普通完整召回 | 约 1 秒待测目标，覆盖调度、本地 query embedding、候选、融合、回源与上下文构建；不含聊天生成和用户手动解锁 |
| 数据库路径 | 暖缓存候选/融合/回源 p95 ≤150 ms，七天词法/时间路径 p95 ≤50 ms，均为待校准目标 |

规模测试分别记录 10 万/100 万消息与实际向量数量，报告冷/暖缓存、近期/历史、有/无写入、重建/正常状态的 p50/p95、错误率、样本数、内存与磁盘。记录数据集哈希、OS、硬件、模型 revision、索引版本和配置；目标机器为用户指定的 32GB 内存、13600K、RTX 4070，尚未进行硬件核验或性能测量。

## Out of Scope

- 内置聊天产品、完整桌宠 UI、多用户 SaaS、公网服务及企业 IAM。
- 自动执行外部任务、训练模型权重、后台自行改核心人设或启用执行规则。
- 首版知识图数据库、复杂图推理、多模态理解、按月分库、分布式组件及通用插件框架。
- 默认云端推理、静默云端 fallback、自动把私人数据上传测试或提交仓库。
- 对宿主未暴露或未持久化内容的完整留存保证，以及对宿主已保存/已外发副本的撤销保证。
- 任意自然语言问题 100% 正确、自动凭证检测零漏检或未经测量的性能保证。
- 本次 Spec 整理不包含业务实现、模型下载、后台任务注册、部署、提交或推送。
