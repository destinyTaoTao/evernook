# Topic views v1

#119 adds optional, user-defined, reconstructable topic snapshots. Core persona, confirmed profiles and raw evidence retain their own controls. No tables or background work are enabled until a trusted definition is created.

`TopicViewDefinition` binds title/purpose/query, entry/session/source/time selectors, published observation topic keys, TTL, source/character limits, refresh interval and policy version. At most 128 current definitions; at most 16 views may be selected by `ContextPolicy.topic_view_ids`, with a separate aggregate `topic_view_tokens` budget inside the existing whole-context budget. Historical `known_at` excludes these current-only views.

Trusted CLI/service commands: `topic-view-define`, `topic-view-control` (pause/resume/delete), `topic-view-edit`, `topic-view-refresh`, `topic-view-tick`, `topic-view-status`. `topic-view-read` requires recall only. Definition/control/edit require recall, maintain and accept; edit additionally requires capture. Model-visible tools gain no maintenance permission.

States are pending, valid, empty, needs_refresh, expired, conflict, paused and deleted. Only valid/conflict expose bodies. Readers verify definition/processor identity, TTL, evidence/control/derived clocks, each original source version and each published observation revision. Invalidation hides the entire old body before background work. Generic contradiction inference is not implemented; finite preference conflicts and already reviewed observation conflicts are identified explicitly.

The optional clock uses exact owned SQLite triggers: complete ordinary original user/assistant/tool insertion advances evidence; eligible source update/delete and visibility controls advance control; observations advance derived. System metadata, partial streams and projections do not count as new original evidence. Raw insert and its clock update share one transaction: failure rolls back capture. Views conservatively invalidate on unrelated eligible evidence too. New writes do not create N per-view jobs; bounded idle ticks coalesce latest targets and rotate one view, respecting refresh interval. Persistent claim tokens/expiry and commit-time clock checks prevent publishing interrupted or stale builds.

Refresh uses bounded raw excerpts from SemanticRecall plus already published observations. Support and counterevidence are admitted together or the entire observation is omitted. Coverage reports post-candidate scope filtering, candidate/source/character limits, missing sources and unperformed generic reasoning. No free model synthesis or automatic observation publication occurs. Processor identity hashes actual installed package Python/worker bytes and embedding identity; upgrade requires a new process/instance. No inherited admission across versions.

Explicit user edit appends an ordinary original user event and updates the definition anchor atomically. It is not an overwrite or persona change. Anchors intentionally remain in the view when historical source/time selectors would exclude them; citations label this `explicit_user_view_edit` scope exception. Original privacy and visibility checks still apply. Request IDs include operation identity; retries return the same original source receipt.

Ordinary context consumes current bounded snapshots. Exactly one just-saved complete ordinary user input may be excluded from the evidence-clock comparison, only when it is the sole subsequent insertion; control/derived changes and any other evidence still invalidate. Source/version/head checks run again after tokenizer work for all retained memory items. A change drops the memory payload rather than retokenizing potentially stale duplicates.

View deletion clears snapshot bodies and definitions, retains a tombstone and original user evidence. Source purge clears affected snapshots and schedules rebuilding. Archives remove only recognized exact owned hooks; unknown SQL remains rejected. Restored runtimes reinstall known hooks. Runtime publication compares topic control tables, so an old archive cannot silently revive newer paused/deleted definitions; use fresh backup or explicit review/reconfiguration. Current original IDs/spans are validated again, never trusted from imported view text. Automatic general ID remapping of old snapshots is not provided.

Rollback: stop selecting view IDs and pause/delete configured views; ordinary raw recall remains independent. The optional clock/schema is retained as control history, not automatically dropped. No default migration, new production dependency or cloud fallback.
