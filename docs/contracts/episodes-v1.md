# 跨会话经历候选 v1

Core0.1.17/#113复用CandidateWorkflow与ConsolidationWorkflow，生成可重建的跨会话原文摘录候选。此层不推断世界事实，不自动确认画像，不更改人设；综合观察另由#118实现。

可信maintain/accept入口：episode-propose接受source_ids（2至16个原始事件、至少两个entry/session）、topic及可选entities；episode-read按candidate_id返回当前可见来源。服务CLI和本机CLI一致。后台策略episode-configure(enabled)默认false；启用后仅在当前调度批次符合范围时追加候选，不承诺发现全部关联，也不静默重解释已完成旧来源。显式propose可指定历史原始来源重建；episode-status显示有效策略。

每条保留完整原文范围的EvidenceSpan及控制/内容版本；投影提供来源元组、角色、用户自述/助手参与/外部材料、发生时间、获知时间及独立来源数。摘要为每来源最多64字符摘录并报告省略长度，完整依据仍可回取。entities只是原文出现的字符串及坐标，不代表实体消歧、身份确认或关系推断。重复来源去重、重复相同请求复用候选，不增信。

总原文最多16384字符，摘要JSON最多3072字符；普通完整original来源才可使用，私密原件不进入维护。候选始终pending_review，即使全局auto也不自动合并。读取时重新生成规范摘录并验证全部原始范围，合法来源ID不能为编造摘要背书。任一来源更正/抑制/删除后整条候选正文不可读，需要用当前来源重新propose；删除按既有派生清理传播。

propose有共享截止时间与取消信号，发布事务提交前复核；提取成功与发布成功分别保留。后台沿用持久租约、崩溃重试、前台优先和暂停栅栏，提交时再次验证episode启用策略。普通恢复审查不复制后台启用设置，恢复后需显式重配；导入须使用新机实际来源ID重新生成。候选不会进入普通每轮context。
