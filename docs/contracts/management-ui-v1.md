# 可信记忆管理页面 v1

对应 [#89](https://github.com/destinyTaoTao/evernook/issues/89)，属于 [Spec #88](https://github.com/destinyTaoTao/evernook/issues/88)。`MemoryManagement` 与可信本地 CLI `manage` 复用同一 SQLite 权威账本，不建立 HTTP 服务，不注册 MCP 或模型维护工具。

调用身份须同时持有 recall/maintain/accept。宿主必须使用与普通 capture/recall 身份不同的维护身份，并在已鉴权、受跨站保护的页面通道中建立真实用户意图；持有维护凭证的本地代码属于可信边界，不防御同账户恶意进程。不能把来自模型的 approved 字段直接转成确认调用。

## 查询

`manage` 的 `read-versioned` 使用与 `read` 相同的参数和授权，返回同一次已核验投影的 `value` 与不含正文的 `token`；`fingerprint` 使用相同参数重新读取并仅返回 token。令牌是按调用身份、参数和实际投影计算的进程内密钥 HMAC；无关审计写入不改变它，服务重启或投影变化会使其变化。它不是全库修改水位：不影响该页结果的修改可以不改变令牌，每次指纹都要重新执行该页的有界读取。直接启动独立 CLI 时每次都有新进程及新密钥，因此不能用它跨 CLI 调用比较；跨调用使用独立记忆服务。该接口本身不推送通知，也不能撤回已交付的正文。dsh 预览页已经实现有界轮询及 12 秒失效租约：令牌变化时刷新，过期、断线或进入后台时清空；浏览器事件循环暂停期间不能保证及时清空，具体覆盖与尚未完成的验收见 #134。

`fingerprints` 接收 1 至 3 个只含读取参数的请求，依次独立鉴权及读取，并按输入顺序返回 `tokens`；任一读取失败时整个请求失败，不返回部分结果。这些投影不是同一数据库快照，不表示多页面之间具备事务一致性。该批量接口只减少传输和进程启动次数，不改变每个投影的复核要求或读取成本。

Core 0.1.50 / dsh preview.45 的可信诊断增加候选抽取模型的服务配置状态，仅返回已配置本地或未配置；旧服务缺少字段时显示未知。配置状态不是模型健康或质量检查，不显示路径、密钥或记忆正文，不改变维护权限与日用准入。

Core 0.1.52 / dsh preview.46 新增只读“伴侣人设”页，通过可信 `manage` 的 `persona` 投影展示当前非空人设分块、版本和正文；它与当前注入使用同一人设注册表。仅当设定来源仍为当前可读的完整用户原话且状态版本未变时返回来源 ID，点开时再次鉴权读取；不返回维护理由。人设是用户确认的独立设置，撤回来源不会自动改写人设，页面对此明确提示。该页复用版本化读取与失效租约；旧 Core 不支持该投影时显示不可用，不能将旧结果继续展示。修改仍走可信维护入口，不由此页或模型直接写入；不要把保险库秘密录入普通人设。

## 预览与确认

`{"action":"preview","operation":...}` 支持 source_suppress、source_correct、profile_confirm、profile_reject、profile_suppress、profile_revise。源操作带 message_id，更正另带 text；画像操作带 tag_id，修订另带 label。未知字段/操作、敏感新正文、受保护来源修改、争议澄清画像均拒绝。

Core 0.1.53 增加可信 `persona_set` 预览／确认，操作为 `{"kind":"persona_set","block":"tone","text":"合成：温和"}`；允许的 block 为 identity、tone、boundary、address、state，空字符串明确表示清空，纯空白及凭证格式文本拒绝。预览绑定调用端、精确操作和当时的分块版本；确认后将用户输入原文（清空时为非空确认记录）、新的人设版本及幂等回执放在同一 SQLite 事务，版本已变则拒绝旧预览。预览、确认、取消以及直接人设设置／回滚在取得写锁后重新检查调用端权限；返回的 `confirmation_id` 是对应用户原话或清空确认来源。模型不能直接确认或写入人设，真实用户确认仍由可信宿主建立；此服务端操作本身不提供页面编辑入口，也不应接收保险库秘密。

预览绑定调用端、操作HMAC、目标和证据版本，来源操作还绑定已知画像/事实/经验依赖ID与修订；超过依赖上限明确失败。预览有效期5分钟，每端最多64项待确认。持久表只保留HMAC、ID、版本和精简回执，不另存证据正文。详情摘要明确 total，完整来源另行分页。

`{"action":"confirm","proposal_id":...,"operation":...}` 必须由可信宿主在用户确认后调用。完全相同的操作才匹配；提交前同事务重新检查预览有效期、来源和目标状态及版本。确认记录、原话替代/画像决定、来源控制与实际回执同事务提交；失败不留下半次确认。相同调用端和操作重放返回原精简回执，结果不确定时可用此路径回查；已经完成的回执不保证目标此刻仍处于同一状态，当前状态须重新查询。

`{"action":"cancel","proposal_id":...}` 持久化撤销尚未执行的预览；重启和旧确认请求不能使其重新生效。已提交的变更返回原实际回执，取消不会撤销已提交事务。页面关闭预览和 Escape 均走取消；断连/卸载不保证用户取消已到达核心，未取消预览仍由有效期与版本检查约束。

画像修订使用用户在页面输入的新标签作为新的用户证据，并在本次真实确认的同事务内完成修订与确认；不改写旧原文。来源更正将新用户原话追加为替代来源并保留旧档。移出画像不禁止原话检索；来源抑制不承诺屏蔽其他独立来源或全库同义表达。已经交给宿主/provider的内容不会被撤回。

`rejected` 视图列出原始用户拒绝，`profile_reopen` 将其经真实用户确认重开为草案；继承拒绝的新tag不能代替原始决定重开。跨处理器防重复用真实拒绝事件，按类别、规范化标签和来源版本/片段确定候选身份；不承诺开放域同义屏蔽。超过每类1000条拒绝检查上限明确失败，旧并行草案不能通过确认绕过拒绝。详见 [#90记录](../reports/dsh-ui-02-rejection.md)。

原始记录的物理删除、恢复、独立事实决定、争议裁决、人设编辑和保险库明文不在本页面入口范围内。本契约不把接口存在当成安装、浏览器或正式日用验收。
