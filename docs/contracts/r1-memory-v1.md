日期：2026-10-29。对应 [Issue #5](https://github.com/destinyTaoTao/evernook/issues/5)。**状态：用户确认本机可靠底座路线；备份目的地、启用与恢复验收明确列待办。** 本契约允许继续不依赖备份交付的 T05–T08；不能把备份待办解释为备份已通过、可启用保险库或可进入所有后续阶段。以下逻辑操作与 JSON 是外部行为设计，不是已存在的 HTTP 端点、SDK 或成功运行结果。

## 已确认的路线与运行边界

- 独立 Python 3.14 + SQLite 原文账本，薄 TypeScript dsh 适配；模块化单体，一个权威证据账本。见 [ADR-0003](../adr/0003-r0-evidence-ledger-and-retrieval-reuse.md)。复用检索组件不另建原文真相源。
- 首验平台为当前 Windows 11 x64，实测 i7-10700、约 32GB 内存、Intel 集显；不沿用原 13600K/RTX4070 的性能假设。候选运行目录 `E:\EverNookData` 随平台建议获确认；本次只记契约，未创建日常运行库或访问凭证。
- 首版可靠存储限定本机固定 NTFS 文件系统；当前 E 为 NTFS。不把 SMB/共享盘、同步盘、FAT/exFAT 或其他文件系统冒充已支持，数据库不能直接放网络共享。
- 首个实现版本以已实测的 Python `3.14.4` 为基线，SQLite 使用该解释器自带版本并在启动/验收中记录实际版本；不编造 SQLite 已冻结版本。单写入、短事务，模型推理和用户交互不能占事务；自动抽取/embedding/重排未通过准入时不启动，不预留 GPU 常驻任务。
- dsh 兼容基线为已测 `0.2.1-rc.3`，Node 探针 `24.11.1`；[T01 显示补充](../reports/r0-dsh-display-2026-10-29.md)仅验证内核发布事件前可加屏障，不代表桌面插件已经安装。调用端协议和能力握手须单独检查，不仅依赖版本字符串。
- 原生插件与 MCP 使用同一权限/记忆契约；本机连接不自动取得权限。部署后的调用端配对、凭证文件权限和版本握手必须有回归，不能借接口直调绕过。

## 来源、重试与保存状态

来源身份使用入口实例、会话、分支、源事件 ID 的完整组合；入口实例必须与已认证调用端的准入范围一致。会话或源 ID 缺失时拒绝，不能临时随机一个新身份来掩盖重试。相同来源同内容重试返回原回执、原消息 ID 和原接收时间；不同内容返回 `source_conflict`。相同文本的不同真实事件分别保存。

保存契约覆盖角色、源顺序、源事件时间、模块接收时间、原件/投影版本、完成状态及来源。源时间可缺失并显式表示未知，不能用导入时间伪装；模块接收时间使用 UTC，原始带偏移时间保留，不隐式改变经历顺序。文本严格 UTF-8，非法代理字符/编码明确拒绝，不悄悄替换。普通原文保持接收时内容，检索归一化只能派生。

确认提交前的状态与可靠保存状态必须分开。`accepted`/`pending` 不代表已保存；`committed` 只有在事务与所需恢复材料可靠提交后返回。保存范围为普通原件、脱敏投影或受保护原件，不能仅靠一个布尔 `success` 混淆。磁盘满、忙锁、提交或关联中断不返回相同成功回执。

合成示例（字段是逻辑契约）：

```json
{
  "contract_version": 1,
  "source": {"entry": "synthetic-dsh", "session": "s1", "branch": "main", "event": "u1"},
  "role": "user",
  "sequence": 1,
  "occurred_at": "2026-10-29T10:00:00+08:00",
  "completion": "complete",
  "text": "合成原话：37.50元。\n甲🙂é乙"
}
```

首次提交可靠保存普通原文后返回一个稳定消息 ID、`committed`、`representation=original`、`content_version=1`、`original_saved=true`。相同 source/text 重试返回同一回执；将同 source 的 `37.50` 改为 `38.00` 必须冲突。把 event 改成 `u2` 的相同文本是第二条证据。

## 原件与投影坐标

字符坐标按 Unicode code point，使用 `[start,end)`，不按 UTF-16 code unit、UTF-8 字节或用户可见字素数计数。例：`甲🙂é乙` 共 5 个 code point；`[1,2)` 是 `🙂`，`[2,4)` 是 `e` 加组合重音。TypeScript 适配器必须显式换算，不能直接用字符串 length/slice 充当该坐标。

每个引用绑定表示类型、表示 ID/版本与内容版本。原件和脱敏投影有独立坐标；不能用投影偏移反读原件，不能在修改版本后接受旧片段定位。未知目标、非法区间、期待版本不符或片段原文不匹配须拒绝；超长回取分页并显示范围/剩余状态，不能静默截断。

## 显示前的可靠流式保存

**用户已确认必须保全显示过的助手流片段。** 不能选“先展示，等最终消息落盘后再补齐”的降级路线。输入在模型调用前可靠保存，输出在实时展示前可靠提交；耐崩溃发件箱也必须返回明确的持久化确认。

流标识至少绑定来源会话/分支、逻辑输出、模型尝试和片段序号；尝试在派发请求前具备可恢复身份。相同尝试/序号同内容幂等，不同内容冲突；丢失前序或乱序明确处理，不以排序后拼接假装完整。重试是独立尝试，不能混入旧尝试的完成文本。

调用端只有取得该片段对应的可靠保存回执后才能发布展示；存储失败必须阻断该片段显示并报告失败。被显示的文本必须与持久化的可恢复表示一致。片段已提交但尚未显示的窗口允许多保存，不能出现已显示但没有保存的窗口。`partial`、`complete`、`canceled`、`failed` 与已知缺口分别标识；没有 finish/最终确认不能推断成功完成。

逻辑示例：attempt `a1` 的 chunk `0` 保存成功后可显示；chunk `1` 写失败则不能显示。若显示 chunk `0` 后强杀，恢复必须逐字取得 chunk `0` 并显示未完成状态。最终消息回扫可补充完成信息，不能替代此前片段账本。实际桌面全部展示通道和恢复回放必须在 T10 集成验收；不能把 R0 原生事件实验等同于已满足产品保证。

## 敏感分流与关闭保险库时的行为

可选保险库保持关闭，不影响普通记忆底座开发，但不授权普通路径保存敏感原件。在诊断日志、持久化、query embedding 或其他模型调用之前检查显式敏感标记、工具来源与适用检测规则。检测不是零漏检保证，必须记录覆盖边界并保留人工标记入口；请求里的“无需脱敏”不能关闭强制检查。

遇到声明或检测为受保护内容时，只能可靠保存安全脱敏投影并返回 `projection_only`、`original_saved=false` 与缺口；不能生成可信投影则明确拒绝/隔离，不能回退明文。原始秘密及可用于离线猜测的公开低熵明文散列不能落普通账本/幂等索引；敏感输入的冲突校验必须用独立受保护的校验材料或拒绝不具备安全校验条件的请求。具体检测实现与密钥材料生命周期必须通过 T05 对抗回归。

流式敏感内容同样先分流再入 journal。无法安全判断的分块不得先写普通库或先显示；可先等待安全分类/投影，不能为保持逐 token 展示绕过检查。保险库关闭且未保存原件时，不显示无法恢复的原始秘密；可展示已可靠保存的投影并说明原件未保存。不可检查附件不入普通索引，附件原件/隔离与缺口留给 T08，不能冒充文本处理已覆盖。

## 备份与恢复策略

用户确认采用独立磁盘/外置盘的加密快照：每小时一次保留 48 小时、每日一次保留 30 天，RPO ≤1 小时、RTO ≤1 小时作为验收目标。C/D/E 已核实同属物理磁盘 0；跨这些盘符不能称为抗磁盘故障。当前其他映射盘是网络共享，未获指定，不自行用作备份目的地。

**用户已明确将备份目的地、启用和恢复验收列为待办。** 普通文本可靠底座可继续实现；T09 的备份部分及日常/长期运行验收仍受此项约束。在目的地、独立性、加密恢复材料和恢复演练未闭合前，不启用计划任务，也不宣称备份/RPO/RTO 达标。小时/日保留须保有可恢复的实际快照，过期清理不能先删掉唯一可恢复副本；只有恢复演练通过才报告策略有效。

备份加密独立于可选凭证保险库的开关，不允许因保险库关闭而明文备份。日常加密写入不需要把主口令放进任务、配置、环境变量或命令行；恢复材料保管和恢复 UI 在备份能力实施前落实。备份缺失、失败、离线目的地或未验收必须以真实状态显示，不因存在一个复制文件就声称达到恢复目标。
