# 受控运行库发布 v1

2026-11-08：[隔离dsh切换验证](../reports/dsh-runtime-cutover.md)已核对实际wheel、新配对、同一测试profile重启、重要原话/控制/可靠流与只读恢复，旧源库保持冻结；该合成验证不代表用户库、跨机器或物理系统验收。

对应 #66。可信 Python 维护入口 `evernook.runtime_restore.publish_replayed_runtime(runtime, access, source, destination, checkpoint=..., client_id=..., entry=...)` 返回新配置路径和新 `Access`。调用者必须具有 `admin` 与 `archive_review` 权限，提供独立保存的认证检查点及经过 #65 控制重放的归档。

发布前锁定来源账本写入，并重新核对归档认证、完整性与检查点。普通消息、重要交代和关键持久化版本必须完整；快照缺少后续普通证据或版本时返回 `archive_evidence_incomplete`，应重新导出并重放，不能通过忽略缺口发布。当前任务状态从受锁来源同步，避免恢复旧进度或漏掉新增控制证据的处理任务。派生索引可以通过正常维护入口重建。

0.1.1 起，自动偏好 processor 的准入设置也绑定控制头及发布前水位比较。仅撤销准入、保持 tier/categories 不变，也会使旧检查点失效；给旧快照重放新控制头不能恢复已撤销准入。需要重新导出当前快照并捕获新检查点。尚未使用该可选设置表的旧控制头身份保持不变。启用过该模块的旧检查点应重新捕获；升级前停止旧宿主，不能把旧版本继续运行视为已应用修复。

2026-11-08 起，页面管理预览/取消/完成及只读续接授权/完成的三个可选表也参与控制头与发布水位。创建、取消、确认、完成或清理预览后须重新捕获检查点；已经使用这些表的旧检查点不能沿用。控制重放不会替旧快照补造授权回执，状态不一致返回 `archive_evidence_incomplete`，应停止旧宿主并重新导出当前快照。未创建这些可选表的库保留既有控制头。当前快照可保留原调用端的回执，但新运行库不继承旧令牌；只有维护者重新显式配对相应身份才可回查。Core 恢复不创建 dsh 会话、不解封旧会话或授予工具执行，真实宿主切换仍需单独验收。见 [#98 验证](../reports/dsh-control-restore.md)。

新身份独立生成，不继承旧客户端令牌，也不自动获得归档审查权限。为保留既有来源、控制决定的幂等语义，HMAC 密钥由可信来源直接写入新 owner-only 目录；它不会写入普通归档。来源不可用或保护材料缺失时拒绝发布。本入口不是来源账本与保护材料同时丢失后的灾难恢复，也不解锁保险库。

全部文件在目标父目录的私有临时目录构建，运行时校验后以目录重命名发布。目标已占用、版本不兼容或校验失败不覆盖既有目录。发布前中断可以重试；发布后回执丢失时，相同参数和仍匹配来源的检查点通过认证发布记录取回原身份。该重试只适用于目标数据库与身份材料自发布后完全未变的情况；正常使用（包括写审计的读取）也可能导致重试被拒绝。数据库丢失、回滚或修改不触发自动新建、覆盖或重新认证。完整状态摘要逐表编码并排序，尚未测量规模内存与耗时。

恢复库是一次性切换时的独立副本；没有双库同步协议。维护端应停止旧宿主并将所有入口切换到选定的权威运行库，不能同时向两个副本写入并期待后续更正/删除跨库传播。旧账本、普通归档、加密备份与宿主已交付副本仍然存在，不会自动删除或远程撤回。临时文件也没有取证级安全擦除保证。

本地合成测试覆盖正常采集、逐字回取、来源回取、重要交代、附件、抑制、来源幂等、任务数量、发布前失败和发布后回执丢失重试。尚未进行物理掉电、规模恢复性能或真实宿主切换验收。
