# 0015 — 全历史精确候选与独立检索意图

状态：已采用；#112功能验证与日常准入分别记录。

## 背景

旧语义候选按接收顺序最多扫描10000个片段。索引ready只证明已处理来源，不能证明候选能覆盖全历史。长宿主输入还分别截取开头256码点或省略查询，导致尾部问题没有检索机会。#121已冻结跨年、未知年份、长输入、控制失效及位置夹具。

## 决定

继续用权威SQLite中的semantic_chunks_v1及现有模型/切片身份。全历史、当前可召回版本先计算精确cosine候选，每来源取最佳片段，再截取100个候选参与既有RRF；最终输出额度独立。显式since/until在候选截断前过滤；未提供时间条件时，未知发生时间仍有全历史机会。最终回源和控制版本复查保留。

可选`vector`extra固定sqlite-vec0.1.9，在每条本机连接上短暂允许加载已安装包提供的扩展，随后关闭扩展加载。使用C标量距离函数查询普通表，不使用vec0虚拟表，不复制向量或增加远程服务；未安装/不能加载时使用Python精确扫描。返回实际backend身份。选择依据是原prefix、Python完整扫描与C完整扫描的同一位置内核对照；原路径漏末位，完整路径均可达，C小样更快。完整产品的规模性能仍需实测。

[上游Python文档](https://alexgarcia.xyz/sqlite-vec/python.html)说明连接级加载方法；[KNN文档](https://alexgarcia.xyz/sqlite-vec/features/knn.html)支持在普通表使用标量cosine；[固定发行版](https://github.com/asg017/sqlite-vec/releases/tag/v0.1.9)与[Windows wheel](https://pypi.org/project/sqlite-vec/0.1.9/)作为依赖来源。没有采用尚需额外验证的ANN预发行版。

原始输入保留并全量经过凭证/编码检查，检索意图是独立参数。显式短句最多256码点；没有显式意图的长输入只选择可定位的尾部，报告query_coverage_limited及起止坐标，不能宣称理解了所有被省略内容。Core、context、HostContext、MCP/service及dsh/pi使用同一策略。安全短句不能绕过完整原文保护。

真实位置夹具揭示：固定MiniLM在“学会水上划行”与“学会独木舟”的相似度.355，低于原.4阈值。保留这个失败，不降低阈值；复用ready FTS提供中文双字/英文词的有界OR候选，与原精确、词法、近期及语义通道通过RRF融合。先按合法来源去重再取100个来源，每通道对每个来源只投一票；兼容现有重复FTS行。无需另建实体图或新tokenizer依赖。词法未ready时保留对应覆盖缺口，策略变化在评测配置中单列。

配置了embedding与维护身份的独立服务在空闲时每tick最多处理1片段、5秒上限，前台/暂停/退出可取消。取消/截止时间覆盖数据库、推理和发布前检查。普通语义错误不阻断独立的词法/导航/沉淀任务。模型身份与来源版本仍决定重建和发布资格。

## 影响与回退

没有原始数据迁移或向量格式迁移；旧索引直接可读。卸载vector extra可退回Python查询，保留同一账本；模型换版仍按space隔离并重建。Core0.1.16、dsh preview.23提供新参数及长输入行为。

全历史精确搜索仍是线性成本，可选C只降低距离计算成本，不能据此承诺百万来源p95。继承#81/#84的质量、完整轮次/热候选/近期词法、资源和独立规模门槛，失败/missing继续阻止日常准入。实体/事件图与模型重排要等可追溯的派生资产及增益证据，不因借鉴Hindsight就另建缺乏输入质量保证的关系库。
