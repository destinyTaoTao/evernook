# 原文账本独立保全，检索组件按验证结果复用

用户于 2026-10-29 确认采用独立 Python 3.14 + SQLite 原文账本、薄 TypeScript dsh 适配，先在当前 Windows 本机推进。根据 [T01](../reports/r0-dsh-2026-10-29.md) 与 [T02](../reports/r0-core-2026-10-29.md) 的实测，由小型本地账本负责原文、幂等回执及后续更正/抑制契约，再评估复用成熟检索组件；不将 MemOS `2.0.16-beta.1` 原样作为唯一权威证据账本。其内核有可运行的多路检索与维护能力，但长原文的公开回取、原地修订、抑制语义及 dsh 版本范围仍需适配；最小自建原型也缺少完整事实时间语义和无答案控制，不能因小样本命中较高就认定全面胜出。

代价是自行维护可靠底座与宿主适配；收益是原始证据不受派生记忆组件的裁剪和修订语义支配。此次确认接受上述架构、语言与首验平台，embedding/抽取模型仍是候选，可选保险库保持关闭。用户还要求显示过的助手流片段必须可恢复，并确认独立磁盘加密备份的频率、保留期与恢复目标，随后明确将备份目的地、启用及验收列为待办；普通文本底座继续推进，备份、实际宿主显示接入及后续模型/质量门禁分别保留。详情见 [R1 契约](../contracts/r1-memory-v1.md)；共享身份与凭证边界继续有效。
