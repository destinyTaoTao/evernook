# 百万条中文关键词候选的精确 BM25 分数界

在同一份百万条合成账本上，高频查询仍匹配并计算全部 FTS 分数。先用一小批匹配的分数确定入围上界，可以跳过大多数 FTS 内容行的读取和消息 ID 排序。两轮对照中，六类查询的有序消息 ID 列表摘要均与基线一致。

## 入围条件

SQLite FTS5 的 `bm25(lexical)` 分数越小，排名越靠前。先在同一 SQLite 读快照中，从完整 OR 查询取最多 8,192 行，只读取分数。若样本至少有 256 行，且存在比分数第 256 名更差的样本，将第 256 名的分数记为上界。全库至少有这 256 行达到上界，因此分数更差的行不可能进入全库前 256。第二次 MATCH 保留所有小于或等于上界的行，沿用原有 BM25、消息 ID 的二级排序。分数界对样本的选择顺序没有要求。

这保留了高频词对匹配与评分的贡献，也保留了出现在样本之后的独有词和边界同分行。样本过少或没有较差分数时直接按原前缀查询排序。前缀中的消息需要经过版本、可见性、当前输入排除和范围校验，足量性条件不满足时沿用完整排名回退。已取得完整窄时间范围时先执行既有范围查询。实现没有新增索引或运行时配置。[实现](../../src/evernook/semantic.py) · [迟到的独有词、同分、版本失效及抑制回归](../../tests/contracts/test_keyword_score_bound.py)

## 同库测量

基线为 `d929d1b`。在 Windows / Python 3.14.4 下，分别加载冻结基线和候选的实现，使用同一个 6,201,389,056 字节的离线合成 SQLite 夹具。探针用 `mode=ro&immutable=1` 打开文件，确认 WAL 为空，运行前后核对源库长度与修改时间。测量顺序为基线、候选、候选、基线。下表为 `_keyword_ids` 单次墙钟秒数，包含 FTS 排序、来源校验和完整候选 ID 读取；每行两次。每个查询的有序 ID 列表均核对 SHA-256。[只读测量探针](../../probes/semantic/keyword_score_bound.py)

本轮只检查关键词阶段。基线和候选的页缓存与机器负载未固定，两个样本不能估算稳定 p95。完整召回还包括语义向量扫描、词法覆盖、回源和宿主开销。百万库的一秒端到端目标仍待验证。
