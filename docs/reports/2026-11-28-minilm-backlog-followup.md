# 百万库的待索引来源选择与后台恢复

## 第一条来源

原账本保留了上次 120 对混合读写的 120 份回执。按回执 ID 回读原文、来源、内容版本、可见状态和当前分块，120 条均未获得当前空间的 MiniLM 向量，其中 4 条已有词法索引。原文与回执的有序 SHA-256 为 `9e61db0f798935d3715caad1126b9102f2d5c2870bf460f59f449c2cb0a11c67`。

| Windows 实测 | 结果 |
| --- | ---: |
| 0.1.99 原账本旧选择 SQL，限一条，推理前中断 | 5.001 秒 |
| 0.1.100 从原账本副本重新核对覆盖并发布 | 56.505 秒 |
| 最终写事务，从 BEGIN IMMEDIATE 到开始执行 COMMIT | 0.232 秒 |
| 核对后，按原顺序选取第一条 | 1.497 毫秒 |
| 正式 refresh，限一条、5 秒预算，含真实模型与提交 | 1.630 秒 |

旧查询在返回首条之前逐一检查已有百万文档及其分块。原账本已有检查点，但服务按需建表后，数据库的 schema 版本从 127 变为 135。仅检查当前触发器定义不足以证明过去的每次变动都被记录。后台对显式启用且结构匹配的旧检查点执行一次权威核对，在读快照中暂存差异，发布前复核并发写入、前台活动和权限。前台写入改变数据版本时放弃本次结果，下一轮可重试。新选择查询用未覆盖来源的稀疏索引和发生变动的来源 ID 构成候选，按原接收时间及 ID 确定顺序，回源核验资格、版本和已有分块。前台读取的 100 项差异核对上限保持原值。

在保留原账本的独立副本上测试。一次旧版维护用于观察调度耗时，语义仍有 120 条积压。随后安装 0.1.100，使用原 MiniLM 配置和正式维护身份。首条返回的 ID 与旧负载第 0 轮的写入回执相同，提交后全库 1,000,001 个向量、119 条语义积压。该样本仅计一次选择与刷新。wheel SHA-256 为 `c7a6720e5dd44f0b7bceea04f757ba569b799ec95a2720b8f378484b9f967704`，117 个 Python/JS 模块与代码逐文件核对。安装包的语义检查点与服务维护回归共 19 项通过。

## 同一批 120 个原始回执

Core 0.1.101 在**原账本**上开启正式后台服务，保留默认 5 秒轮询和每次语义刷新 5 秒预算。观察程序每约 5 秒只读核对 120 个原回执 ID，比较原文和回执摘要、词法 ID 命中、向量空间、状态版本、内容版本、分块范围和长度。过程中只有服务负责建索引。下表为首次观测到的就绪时间，从维护服务发布端点开始计算。

| 达到的状态 | 用时 | 同批词法覆盖 | 同批语义覆盖 |
| --- | ---: | ---: | ---: |
| 服务启动 | 0 秒 | 4/120 | 0/120 |
| 首个模型批次已提交 | 70.33 秒 | 4/120 | 16/120 |
| 全部原回执具有当前版本的向量 | 529.325 秒 | 68/120 | 120/120 |
| 全部原回执也通过词法核对 | 966.070 秒 | 120/120 | 120/120 |

最终公开状态显示词法和语义各覆盖 1,000,120 个来源，积压及失败分块均为零。原文与回执摘要在每次采样中一致。另经公开召回，用最后一条的原文提问，得到相同来源和 ID，排名第 1，未报告降级；sqlite-vec 精确扫描 1,000,120 个分块。[逐批进度与公开状态](2026-11-28-minilm-backlog-recovery.json)

旧版副本诊断中，一次完整维护轮用时 122.00 秒。词法刷新一条花了 29.97 秒（含状态统计 14.82 秒），随后归纳调度触发用时 41.36 秒、调度状态用时 30.06 秒，末尾再次统计词法用时 15.41 秒。0.1.101 按原有每批上限一次准备最多 16 个语义分块；词法每次选取最多 16 个来源 ID，若同步选择已占满 1 秒窗口，下一轮按 ID 重新读取原文并逐条提交。耗时的同步选择本身仍可能超过 1 秒。调度器返回的词法状态复用同一快照。一次任务耗时与默认轮询间隔都会影响实际追平速度。

## 后台处理中强停

一次安装态回归在 20 秒等待结束时仍未处理第二条来源。测试在看到第一条处理计数增加后立即终止服务，这时上一轮调度租约可能仍有效。分别在 0.1.99、0.1.100、0.1.101 的专用小账本上锁定这个时点后强停，重启均先报告 `candidate_run_busy`，随后在原租约到期后自动完成第二条；三次观察总时长分别为 33.686、33.374、33.245 秒。三版互斥行为一致。

回归现在分别覆盖在已确认暂停的两轮之间重启、以及持有效租约时强停。后一项核验租约有效时维持互斥，并实际等到原租约到期后核对第二条完成。0.1.101 安装态合跑服务维护、词法窗口、语义检查点三个模块，33/33 通过，66.910 秒。该实验使用进程强停，物理断电需要单独验收。[进程回归](../../tests/contracts/test_service_maintenance.py)
