# T22 加密收件增量验证

实现与范围见 [契约](../contracts/protected-inbox-v1.md)。使用 Windows、Python3.14.4、PyNaCl1.6.2，全部为仓库外合成输入，未接触私人凭证、初始化日常运行目录或修改宿主配置。

验证覆盖锁定写入、测试端独立解密核对完整 Event/绑定（产品普通 API 不提供解密）、普通原文和 FTS 无哨兵、所有落盘文件无明文/公开低熵散列、并发重试与来源冲突、核心 INSERT 故障后的待关联状态、实际子进程退出于密文提交后和核心提交后、调包/篡改/错接收材料/错账本绑定拒绝。

测试初次运行6项，171.131秒，行为断言通过但3项清理错误：测试用 SQLite context manager 没有关闭连接，Windows 拒绝移除临时数据库；改为显式 closing，不涉及产品路径。修正后6项通过，193.722秒。进一步增加加密故障、签名材料缺失、普通引用丢失修复及真实 CLI 哨兵/非TTY口令拒绝3项，通过83.292秒。mypy核心及相关测试16个文件通过；没有加密依赖的环境能导入普通核心，未加载nacl。

保留限制：Event正文的显式 opt-in 接口，自动分流/附件/流、受保护备份及明文授权 helper 尚未实现；不关闭整张T22，不启用生产能力。进程退出测试不是物理掉电或硬件故障测试。
最后新增关联核对后，受影响的并发与两个进程退出窗口2项再次通过，80.235秒。
