# 百万条近期与历史召回分阶段实测

夹具为百万条合成来源，均有 384 维合成指纹向量。先复测共享向量扫描的阶段耗时，再验证字面渠道复用同一 SQLite 读事务的覆盖检查后，公开召回时延和完整结果的变化。

## 复现

按共享扫描探针准备两份冻结源码和同一份外部 SQLite 备份，以独立进程从同一副本调用公开 `SemanticRecall.recall`。近期查询为「合成条目0999999」，历史查询为「合成条目0000001」，各四轮，每条查询交替两臂先跑顺序。按原方法报告端到端墙钟时间和完整页面。逐对比较时保留 `semantic_scanned_chunks`。[共享扫描探针](../../probes/admission/recall_shared_scan.py)

计时探针在运行时包装 `MemoryRuntime.search`、`_search_index`、`_search_hits`、`SemanticRecall._keyword`、`status`、`_semantic` 以及最终的 `read` 和 `state`。候选另外计时 `_search_coverage` 和 `_search_snapshot`。记录每个调用的 `perf_counter` 和 `process_time` 差值以及调用数。使用 SQLite Connection 子类对覆盖汇总、BM25 和向量排序 SQL 计时并保存 `EXPLAIN QUERY PLAN`。阶段计时中的嵌套值单列，避免和外层重复计算。
