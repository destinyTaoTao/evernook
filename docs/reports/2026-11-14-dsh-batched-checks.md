# 页面与弹窗复核批处理

Core 0.1.32 的可信 `fingerprints` 将最多 3 个页面投影检查放入一次服务调用；每项仍分别鉴权和读取，任意一项失败时不返回部分令牌。dsh preview.36 将当前页及已打开的来源／历史令牌一起提交。各读取不是同一个 SQLite 快照，原 12 秒失效和后台清空边界不变。

在仓库外隔离账本上，以同一已安装 Core 0.1.32、相同 timeline 与 source、交替执行 5 组，两个独立 CLI 调用的墙钟中位 1975 ms、最大 2066 ms；批处理调用中位 977 ms、最大 1008 ms。每组核对两个令牌完全相同。样本小、数据少、未采集 CPU 和进程峰值，不构成 p95、规模或日用性能验收；单页仍需启动 CLI，多页仍会各自轮询，#143 保持开放。

实际 dsh 0.2.1-rc.5 隔离安装使用该 Core 和 preview.36，打开合成时间线及来源弹窗后，第二个已配对身份撤回该来源；批处理复核失败，弹窗和页面正文被清空并显示不可用。首次测试脚本错误地读取不存在的 `text` 字段，未执行变更；随后使用实际 `excerpt` 字段完成。已安装 `client.js`、宿主桥接和 Core 管理模块分别与本次源码哈希一致；隔离服务和宿主均已停止。profile 继承了模型提供方配置，未发送记忆到模型或发起推理。

管理与服务源码回归 21 项通过，组件模拟覆盖页面／来源／历史成批检查、变更、超时、后台和迟到响应；宿主跨站／CSRF 与生命周期测试、strict mypy、TypeScript 类型检查和包构建通过。浏览器取消会终止宿主侧 CLI；服务端已开始的投影读取能否及时中止尚未测量。尚未在真实浏览器完成所有事实／观察／历史变化、重启、多页面、大库与系统睡眠的组合验收。浏览器事件循环停止或两次检查之间，旧内容可能暂留；已经交付的内容无法撤回。
