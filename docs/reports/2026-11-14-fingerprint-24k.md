# 指纹复核：24,341 条合成记录的短时对照

对应 #143 / #162。Core 0.1.40 和 preview.41 在 Windows 本机、独立服务上进行一次有界实验。原合成样本目录名称带有 `100k`，但数据库实际只有 **24,341 条**；先以 SQLite 只读备份创建仓库外副本，再单独配置身份并激活副本服务。原库及原配置未修改。实验前后副本的 `quick_check` 均为 `ok`；写入测试后副本为 24,357 条。

六轮单面板、六轮四面板，每个请求复核同一时间线前 24 项；四面板合计 24 次请求。桥接和原 CLI 串行分开执行，按 20 ms 采样其工作进程树 RSS；不包括服务、Node 宿主和浏览器的内存。单面板桥接包含首次冷启动；结果不等于正式 p95。

| 路径 | 单面板中位／最大 | 四面板中位／最大 | 采样工作进程树峰值 |
|---|---:|---:|---:|
| 每次启动 CLI | 1.058 / 1.149 s | 1.400 / 1.484 s | 446.2 MiB |
| 可选指纹桥接 | 0.769 / 1.074 s | 1.113 / 1.204 s | 364.5 MiB |

原 CLI 的四路每轮累计工作进程 CPU 采样中位数为 5.312 秒；桥接 CPU 没有按相同方法记录，不能声称其 CPU 改善。桥接进程树观测到 63 个进程 ID，包含持续进程和短命辅助进程；每次 ACL 等检查仍可能启动系统辅助进程，并非每次复核完全没有进程开销。强杀隔离 Node 测试宿主后，本轮观测到的桥接后代进程均退出。

另用独立配对写入身份各顺序写入 8 条合成记录：空闲时中位／最大 0.320 / 0.332 秒，四路桥接持续复核期间为 0.421 / 0.474 秒。计数窗口内审计分别增加 8 和 19 条；后者混有并发管理复核，不能归因于单个请求或外推增长率。抽查最近 27 条审计的动作和结果，并检查全部审计 action／target 字段，未发现测试正文。这里未做并发取消、强制掉电、长跑、其他数据库规模或多台机器验证。

两种路径都使用当前服务鉴权；实验没有修改前端 12 秒失效边界，也没有评估实际浏览器的渲染成本、跨客户端撤回或主题图规模。这是同机小样本和单一时间线页面，不能解除 #143 的大库、全图、多面板长期负载及日用门禁。
