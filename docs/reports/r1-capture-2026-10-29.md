# T08：工具、文本附件及采集缺口

日期：2026-10-29。对应 [Issue #9](https://github.com/destinyTaoTao/evernook/issues/9)，基线 `ea77ffb`。[采集契约](../contracts/capture-v1.md)在已有本地身份边界上保存工具事件、可检查的有界文本附件及明确缺口；没有生产宿主、MCP 或网络上传入口。

## 实现与验证映射

| 验收范围 | 实现与回归 |
|---|---|
| 工具来源与分支 | 信封保留调用/结果种类、工具名、关联输入、角色、原始来源/分支/顺序/完成状态。同文本不同真实来源或分支分别保存，不推断有效事实 |
| 附件与账本一致 | 可接受 bytes 直接作为 BLOB 与消息/清单/任务在同一 SQLite FULL 事务提交，无事务外对象目录。附件插入触发实际约束失败时整体回滚；关联不存在也拒绝；重试成功，无孤立文件 |
| 幂等与恢复 | 8 线程16次重试得到同一回执、只增加一条消息/任务；工具名或附件内容改变冲突。真实子进程在 COMMIT 前退出无事件/附件关联，回执后退出逐字回取附件和未完成正文 |
| 敏感分流与缺口 | 跨块密码、受保护工具来源及附件声明敏感不落普通原件/公开散列。正文缺失/未完成、附件缺失/未完成/不支持/超限/编码损坏/大小或哈希不符均可按 ID 查询缺口。未知 PDF 等不可检查原件不进入普通存储/索引 |
| 完整性与访问 | 每次清单、附件读取及重试回执核对实际 BLOB 与尺寸/散列，人工注入损坏/缺失后不再报告完整。所有新入口认证；被抑制目标不能经附件或清单绕读 |
| 有界文本检查 | 1 MiB 字母负例暴露旧 URL 检测反复回扫；将协议名前缀限制32字符后通过。专用子进程有20秒超时回归，测试结果不代表产品延迟指标 |

## 环境与结果

Windows 固定 NTFS、Python 3.14.4、SQLite 3.50.4。完整核心 `python -m unittest discover -s tests/contracts -v`：39 项通过，200.876 秒；`python -m mypy`：严格检查12个源码/测试文件通过。耗时含反复启动 ACL 与子进程，不是服务延迟测量。外部原始检查输出：`E:\evernook-lab\r1-capture-20261029`，临时数据库和秘密材料只位于 checkout 外，未初始化日常运行目录。

首版只接受 UTF-8 可检查的文本附件（单个≤1MiB、每信封≤16）；PDF/图像/音频/压缩包只记缺口，未声称其原件或多模态理解可用。分块接口接收调用端提供的块快照，不是实时上传会话或显示屏障；未完成分块保守保存占位投影。没有真实索引/模型/后台消费者；故障注入不是物理断电/磁盘故障。备份按用户决定待办，保险库关闭，dsh 全展示链路仍待 T10 验收。未推送或修改 GitHub 票据。
