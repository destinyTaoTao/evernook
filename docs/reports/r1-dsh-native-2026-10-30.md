# dsh 原生适配实现与合成内核验证

代码、权限和真实支持范围见 [契约](../contracts/dsh-native-v1.md)。运行数据位于仓库外专用临时目录，未接触私人对话、既有宿主配置或生产模型。

实现包括可信 MCP 采集信封/流入口、输入保存屏障、流尝试缓冲和提交后发布、跨会话来源片段注入、工具及有界文本附件、同来源回放与只读重扫。流入口复用原有 capture 事务，不另建记忆数据库。

验证采用 Windows、Python 3.14.4、Node 24.11.1、真实 dsh 0.2.1-rc.3 内核及其 JSONL 后端。SQLite 独立读取连接在 provider 调用和每次原生 live text 发布时核验提交，不以模型说“已保存”作为证据。

已发现并修复：

1. 初版仅注入搜索命中词，缺少周边数值；现在展开仍可见的原文片段与坐标，排除审计项。
2. 原生文件 ID 带 `sha256:` 前缀；适配器严格解析后再传核心完整性校验。
3. 原生 LLM 将 provider 异常归一化为 finish(error)；失败路径检查真实完成状态，不依赖异常一定向外抛出。不完整流保守保存投影。

测试夹具曾在已关闭 turn 后手工追加工具事件，被原生恢复校验正确拒绝；夹具已改为真实 AgentLoop 调用注册的合成工具。该拒绝不是产品缺陷。

验证结果：

- 最终真实内核 6 项测试全部通过，62.021 秒：输入先保存、跨会话来源片段、模型中断不显示、新连接重复重扫、每次 live text 发布前独立读库、敏感输出阻断、真实 INSERT 失败阻断调用，以及真实工具和文本/未取得附件。
- 现有 MCP 11 项通过，137.692 秒；新增可信附件协议与最初 3 项流测试共 4 项通过，17.781 秒。增加不完整流投影回归后，流套件最终 4 项通过，13.788 秒。
- TypeScript 严格类型检查、构建通过；Python 核心及受影响测试 mypy 通过（15 个文件）。未重跑全仓测试或宣称性能达标。

T10 仍有桌面安装、断网、压缩/分支、用户取消、工具结果显示屏障和强杀窗口待办，T09 完整恢复也未验收，因此不关闭票据或启用日常宿主。
