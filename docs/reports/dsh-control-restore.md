# 页面与只读续接控制的运行库发布水位

2026-11-08，实施 [#98](https://github.com/destinyTaoTao/evernook/issues/98)，关联 #94/#82。#97 已提供同一活动账本的只读恢复，本批补齐 Core 独立运行库发布对新增控制元数据的检查，不扩大为宿主会话迁移或工具解禁。

源码复核发现 `management_previews_v1`、`host_recovery_previews_v1`、`host_recovery_operations_v1` 尚未参与 archive 控制头和 runtime_restore 持久状态比较。回归首先复现页面取消、恢复取消/确认/完成后控制头不变。仅在现有两个表清单加入三张可选表；未创建这些表时跳过其控制头编码，保持旧身份。没有新增迁移服务或自动复制授权的重放逻辑。

现在较新预览/取消/确认/完成会使旧检查点失效；给旧快照重放新的可信控制头，也不能跳过发布前的逐表水位比较。缺少当前状态时 `archive_evidence_incomplete` 且目标目录不创建。维护端需停止宿主、导出当前快照并重新捕获检查点，而不是把过期授权转成新的同意。

实际合成验证：

- 运行库恢复14项通过；新增矩阵覆盖页面取消/完成、恢复取消/confirmed/complete共5个断点，分别验证旧快照拒绝、当前快照发布、全部控制行保留、旧身份令牌拒绝。最后扩充的配对子集另测通过：新身份不能取用旧回执，只有显式重新配对原调用端才保留取消拒绝或原 confirmed/complete 状态。
- 固定旧控制头测试向量通过，未使用可选表的旧库身份不变。
- 归档、只读恢复控制及页面管理35项通过；3个相关源/测试文件 strict mypy、差异检查通过。未运行全量套件。

所有数据库、身份与控制数据均为仓库外临时合成数据，测试后回收。本批没有启动用户日常宿主、调用 provider、执行原工具、删除原始资产或改写现有运行库。只读 dsh 会话仍由独立宿主控制；新运行库不自动迁移 dsh JSONL 文件或旧访问令牌，实际多入口切换、物理系统与长期验收仍归 #82；正式质量/规模继续归 #81。
