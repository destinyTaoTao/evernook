# M58-11：dsh 确认式记忆维护

Issue #69 增加独立 `dsh-maintenance` SDK 接线：普通连接仍是 `capture/recall`，独立固定的维护身份经本地 CLI 执行。模型工具只提议，可信宿主展示预览后，只有同会话、预览之后真实保存的原生 user 确认命令才能执行。通用自动批准、助手复述与模型参数不能授权。

重要原件直接持久化并按 Unicode code point 分页，覆盖数字、换行、组合字符与 emoji。来源更正使用已审查的真实替代用户来源；画像沿用 revise→草案→另一次确认，既有候选事实更正保留时间语义。来源抑制会影响依赖事实及下一份上下文。普通彻底删除复用核心精确预览、版本与依赖复查，并报告备份/宿主残留。

对抗审查发现并修复可变配置导致已审查操作改投另一同源库的风险、关闭后子进程仍可运行，以及预览回调诊断外泄。预览/任务数量与完成缓存有界，关闭会取消并等待维护进程。回执丢失测试保留真实提交，仅丢弃首次 CLI 输出；新的原生用户确认取回原决定，来源只产生一次变更。失败预览及预览期间取消均不建立可确认项。

验证：完整 dsh/pi SDK 回归 35 项通过（154.784 秒）；之后新增回执丢失测试及加强取消负例的两个定向用例通过。MCP 15 项通过，scopes 6 项通过；源码严格类型检查（33 文件）、TypeScript 类型检查及构建通过。首次 Python 按模块运行 MCP 时缺少测试辅助目录，按现有测试布局补 `PYTHONPATH=tests/contracts` 后 15 项通过，未更改产品代码规避错误。

Standards 审查要求的提交不确定性验证已补齐；重复配对夹具是非阻断可维护性建议。Spec 审查未发现具体阻断项。此报告仅证明真实 SDK/本地传输/SQLite 配合合成 provider 的行为，不代表实际桌面预览 UI、多插件、系统掉电或日常部署验收。事实抑制以来源为范围，候选生成/首次接纳、人设和受保护来源删除不在本入口内。完整接线与重试边界见[契约](../contracts/host-maintenance-v1.md)。
