## 比较边界

以 `6b21cf1990db53b4d7f38e3ce0f40b4247b883b6` 为基线，`a95f611cec18140fd55cd85912d32311f6e2e7a3` 为候选。两侧都保留原有来源、时间、分块版本索引与词法覆盖检查点。候选通过普通维护入口构建语义覆盖检查点，同时使用该提交已有的 BM25 排名、原生 Windows ACL 检查及召回审计。两侧向量通道均使用 `sqlite-vec-0.1.9-exact` 对原始 384 维向量做精确计算。

源库来自[百万条合成指纹夹具](2026-11-22-semantic-coverage-index.md)的 indexed 侧。探针确认源 WAL 为空，分别创建私有目录并物理复制，核对 SHA-256 后才打开副本。源文件摘要为 `437c2bb19653887eb2d58883637352d401869f8389d35e16dfeb88dfe121e174`。两个固定提交分别从 Git 归档加载，在独立 Python 进程中调用公开 `SemanticRecall.recall`；当前 checkout 的 Core 实现不参与。正式计时之前，各侧先做一次进行中的取消，再完成一次不计分的近期查询。

固定 `as_of=2026-11-04T00:00:00Z`、`limit=10`、超时 120 秒，保留默认相似度阈值、近期窗口与系统页缓存。三类查询均搜索全历史，每次精确扫描 1,000,000 个分块。每一类做两对，同一轮轮换实现先后次序，下一轮反转。整页保存在仓库外，逐字段比较后再计算序列化摘要。计时覆盖公开召回及将返回对象转为字典，建库、首次打开、凭据载入与写出证据文件单独处理。

## 复现

提供一份已关闭且已 checkpoint 的上述百万合成运行目录和一个尚未创建的仓库外输出路径，在含 Python 3.14 和锁定 sqlite-vec 的环境中执行下列命令。

```powershell
python probes/semantic/public_recall_pair.py $syntheticRuntime $newOutput --rounds 2
```

需为两份约 6.32 GB 的独立账本及候选检查点预留空间。输出目录下，`progress.jsonl` 记录阶段与提交，`samples.json` 保存每次调用的分项耗时与计数，各 `<arm>-<case>-<round>.json` 是实际完整召回页。本机输出目录为 `%TEMP%/evernook-e2e-6b21cf1-a95f611-20261126-01`。公开探针只使用已知合成夹具上的本地配对凭据，[对照脚本](../../probes/semantic/public_recall_pair.py) 不打印凭据。
