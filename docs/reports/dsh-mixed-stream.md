# dsh 文本与工具可靠混合流：受限协议

日期：2026-11-07。对应 [#96](https://github.com/destinyTaoTao/evernook/issues/96)，属于 #94/#88，接续 [#95 发布屏障](dsh-tool-publication.md)。正式日用仍由 #81/#82 阻断。

## 实现与不变量

preview.13 新增显式 `streamMode: durable_tools`，必须同时 `toolPublication: true` 并使用发布补丁 v1 的独立 rc.5 宿主。原默认 `durable_text`、显式 `buffered` 的语义保持不变；没有新增服务、依赖或 Core 数据表。

```text
provider 文本 → Core appendChunk 回执 → 安全文本前缀 → 原生实时通道
provider 真实结束 → 原始结构/参数完整回执 → 关闭同一文本流
                → 工具调用帧 → 原生工具 → #95 最终结果保存屏障
```

一个真实 provider 响应只对应一个权威文本流；多个文本块按原生次序汇合，块边界与完整原始帧另存为受输入身份约束的 system 证据及 JSON 附件，不伪造完成帧或额外“完整回答”。工具帧、usage 与终结/重放元数据等待真实结束和完整结构回执；其中较早的结构帧也会延迟后面的可见内容，以保持次序。

只允许规范的顺序文本块与可交错的工具参数块。名称、ID、原始参数与最终块必须一致，同一响应的调用 ID 必须唯一；工具参数先解析 JSON 再筛查，不能用转义字段名隐藏已知凭证信号。跨文本块保留同一敏感尾部，分裂的 UTF-16 对合并后才进入 UTF-8 传输，每次 Core 请求仍限制为 65536 字节。原始帧总量沿用既有硬上限。

实时文本帧只输出规范字段；未经完整保存的 provider 扩展字段不能透传。原始结构与发布对象分离，发布后修改对象不会改写尚待保存的原始帧。解析器/provider 异常不携带未筛查参数进入原生日志，统一为安全错误；Core 保存失败不回退为无回执发布。

实际安装的合成探针增加固定 preface：provider 在结束前检查原生实时通道已观察到前缀，随后 HTTP 驱动经公开 Core 流与附件读取核对。buffered 先按预期失败（`live_prefix_observed:false`），同一安装切为 durable_tools 后 read、实际 Node PTC 和 PowerShell 三场景通过，4 条原生结果/日志与 10 份工具快照一致，前缀均有 complete 的权威流。候选 preview.12 的 HTTP 9 项、设置保存/回读和 profile 生产审计 0 条通过；最终包复验单列在下文。
