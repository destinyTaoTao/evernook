## 机制与验证结果

接收路径仅有可信接收公钥和发送签名能力；原文、来源、对象 ID、版本与密钥 ID 一起封入密文，外层签名绑定相同信息和密文。[SealedBox 官方行为](https://pynacl.readthedocs.io/en/latest/public/#nacl-public-sealedbox)不认证发送者，因此另行验证固定注册的 Ed25519 公钥。来源自称或任意 localhost 请求均不是身份凭据。私钥用 [Argon2id + SecretBox](https://pynacl.readthedocs.io/en/latest/password_hashing/#key-derivation)保护；使用库的 interactive 参数，没有自研加密算法。

| 能力 | 本轮结果 | 证据边界 |
|---|---|---|
| 锁定公钥加密收件 | 通过 | 仅接收公钥的 SealedBox 无法解密，正确私钥逐字恢复随机合成原文 |
| 错密钥/口令/篡改 | 通过 | 错密钥、错口令、修改密文或发送签名均拒绝；没有明文降级 |
| 对象/来源/版本/密钥 ID 交换 | 通过 | 外层签名和加密内部绑定共同校验，交换期待对象失败 |
| 可信材料初始化 | 有条件 | 测试固定生成与传入公钥，运行请求不能更换；实际安装配对、文件权限与恢复材料信任未验收 |
| 两次事务与关联状态恢复 | 通过进程实验 | 加密收件 FULL 提交返回 pending；同一收件库 linked 标记第二次提交后才返回 linked；两个窗口进程退出后幂等补齐。未集成真实普通账本/脱敏投影引用 |
| 独立本地口令输入 | 控件可行，未做人机验收 | 真实 Tk 密码框带遮罩，口令读取后清除，不经命令行/环境变量/日志；自动输入是合成测试，隐藏窗口不是受信任桌面的安全证明 |

## 测试回执

8 项行为测试全部通过，严格 mypy 检查 5 个 Python 文件通过。外部测试输出保留每项名称、子进程退出检查与成功状态；清单保存源文件 SHA-256、依赖和运行环境。收件状态为 `protected_pending_link` → `protected_linked`，成功演示解密逐字一致，明文扫描无匹配。SQLite FULL/真实进程退出仍不代表断电、故障磁盘或所有文件系统恢复验收。

恢复测试基于单 helper 与已配对公钥；新版本写入顺序明确。没有证明同时换版本/交付的跨进程事务语义，没有恢复旧快照后重新应用全部撤销/删除记录，也没有测试受控进程以外的内存/交换文件/宿主日志。Python 释放引用不保证所有密钥副本清零。这些边界不可在后续实施中被“加密已经通过”省略。

## 建议与后续门禁

建议保留 PyNaCl/libsodium 作为成熟原语候选，优先把可选保险库与普通记忆分开；其维护面少于自研算法，但仍须工程化授权辅助程序。暂不选择 KeePassXC 为最终后端：缺少真实锁定收件/非浏览器调用的验证；也不把 CLI 的明文输出接进普通工具通道。[CLI](https://github.com/keepassxreboot/keepassxc/blob/2.7.12/docs/man/keepassxc-cli.1.adoc) 与 [Browser 协议](https://github.com/keepassxreboot/keepassxc-browser/blob/master/keepassxc-protocol.md)仅提供候选接口线索。

生产凭证能力继续关闭。需后续确认/验证公钥初始化与轮换、独立主口令交互、调用端注册与可靠 IPC、锁屏/撤销联动、来源版本并发及密钥/原件恢复。T04 可以先确定 R1 在保险库关闭时只保存脱敏投影并报告原件未保存；这不要求先实现保险库，也不能静默降低普通路径保护。没有部署、推送或改动 GitHub 票据状态。
