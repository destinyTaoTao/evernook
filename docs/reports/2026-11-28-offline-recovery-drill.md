# 11 月 28 日普通账本故障恢复演练

在同一台 Windows 机器的临时目录运行 Core 0.1.98 安装包，三次分别创建新的合成账本、加密快照和恢复身份。安装目录的 117 份 Python / JS 源文件与基线 3b5f10f 逐文件比对一致（统一换行符）。所有计时使用单调时钟。

| 轮次 | 审查、解密并发布完成 | 开始恢复至首次经服务读回并核对原文和回执 |
| --- | ---: | ---: |
| 1 | 254.6 ms | 664.7 ms |
| 2 | 246.5 ms | 612.6 ms |
| 3 | 259.7 ms | 623.4 ms |

每轮先保存五条独立来源并隐藏其中一条，创建快照后再新增一条，并确认隐藏另一条旧来源。移走本轮的源目录后，恢复程序只收到备份、恢复材料和口令。审查回执显示五条记录及 `later_changes=unknown`。显式开放快照、启动新的独立服务后，四条应可见原文及回执逐项相等，快照前已隐藏的来源持续不可见，旧身份读取被拒绝。

**恢复点是快照时刻。** 三轮均缺少快照后新增的那条消息，快照后才隐藏的旧来源均重新可读。如果用户可能在备份后更正或撤回过内容，应先在隔离目的地核对，再向宿主开放。表中时间不含人工核对、凭证重配、备份传输、开机或模型加载。

## 重跑

在有 backup 扩展的独立安装环境中运行 `python -I probes/installed/offline_snapshot_drill.py`。每次运行自建临时账本，只输出样本规模、结果和时间。补充运行已有的 `probes/installed/lifecycle.py --output <新的绝对路径>`，其 22 项断言全部成立，涵盖带当前控制记录的恢复、更正、重要原文、流内容、抑制、清除和禁止重放已清除来源。两种恢复路径的输入不同，不能将后者的当前控制保证用于一份独立旧快照。

源码另外复跑 `tests.contracts.test_recovery` 全部七项，以及 `tests.contracts.test_offline_recovery.OfflineRecoveryTests` 的 `test_crash_before_and_after_atomic_publish_can_be_retried` 和 `test_publish_offline_preserves_snapshot_and_replaces_old_identity`，九项通过。覆盖事务提交前及回执后的进程退出、已确认原文/附件/控制的持久性、原子发布前后中断重试及新服务读取。

## 需要设备的部分

用合成账本在第二台 Windows 设备上验证离线恢复。通过独立介质取得备份和单独保管的恢复材料，在可信终端输入恢复口令，核对备份时间、快照后操作、原文和隐藏状态，再重新配对宿主。记录从取到备份到宿主首次成功读取的总时间。若要验收突然断电时已确认写入的耐久性，另选可承受断电的测试设备和测试盘，按断电前保存到独立设备的回执逐条核对。本次自动演练覆盖同机进程及目录故障。
