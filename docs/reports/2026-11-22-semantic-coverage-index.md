# 百万向量覆盖索引对照

对应 [#262](https://github.com/destinyTaoTao/evernook/issues/262)。一个公开合成库有 1,000,000 条来源、1,000,000 个 384 维向量和零待索引来源。用同一份主库文件创建两份仓库外独立副本。复制时确认源 WAL 为空并核对 SHA-256，使两个副本都保留有效词法检查点。两侧已有来源、时间和词法加速索引。查询代码相同，仅在一侧通过可信维护入口补建分块覆盖索引。

分块覆盖索引以 `space_id,message_id,start` 保持原主键顺序，并覆盖 `state_version,content_version`。SQLite 执行计划确认覆盖查询使用该索引直接复核版本。没有覆盖索引时，从分块主键查找后再读取存有向量的表页。两侧公开状态一致，均为 `ready`，覆盖百万来源、无待补来源、失败分块为零。

候选侧一次构建为 7.736 秒，主数据库文件增加 118,239,232 字节，约 112.8 MiB。构建提交之后词法检查点仍有效。现有语义表已建好时，显式重跑 `prepare-recall-candidate-index` 即可为已有的来源和时间索引补齐该项。旧库可以继续使用原有索引。[维护契约](../contracts/long-term-recall-v1.md#可选来源候选索引)

## 兼容性与复现

最终语义契约 6 项、CLI 生命周期 1 项和变更代码及测试的 strict mypy 通过。回归覆盖先有旧双索引、再建语义表和手动补建覆盖索引，还检查分块部分覆盖、同名触发器冲突、重建及拆除，以及已有词法检查点。独立计划核对发现，省略 `start` 的四字段候选在 SQLite 3.43.1 上会改变等距分块的原文引用。保持原主键顺序的最终定义在该额外诊断和项目目标 SQLite 3.50.4 均保留原引用。补充诊断使用 Python 3.12，项目验证环境仍为 Python 3.14。[语义契约测试](../../tests/contracts/test_semantic.py)

复现时从[词法覆盖检查点实测](2026-11-22-lexical-checkpoint-scale.md)的启用侧开始。确认已关闭写入、WAL 无待提交数据，复制原数据库并核对摘要，给两侧配置仓库外合成运行目录。只对候选副本执行准备索引的命令。两侧以 `合成条目0999999` 和 `合成条目0000001` 执行近期和历史查询，窄窗口重用历史查询并明确起止时间。调用中单独计时语义状态读取，保存完整结果并按上表比对。探针和原始输出保存在本机 `%TEMP%` 的 `evernook-262-recall-d34e89a277714da696da2586ab89d0b3` 目录。

对照仅覆盖同机、保留操作系统缓存、固定合成指纹和三种查询。没有包含真实模型推理、写入竞争、重建期间延迟或正式全矩阵。完整召回仍高于一秒门槛。
