# M58-15：pi 可靠文本发布与恢复

Issue #73 复用 #72 的 durableText 和 #71 的核心 capture_chunk/read_stream。显式 durable_text 单文本块模式先初始化流，再启动委托 provider，每个 native text_delta 在核心提交后入队。pi 的可变 partial 和原始 provider 观察事件不能透传，SDK 快照只由允许发布的累计文本重建。length/取消/provider 失败保留未完成状态，原生 settlement 不另行导入完整答案。

streams/readStream 从持久标记发现并分页读取；与 dsh 共享客户端账本搜索、来源、幂等及保护机制。默认 buffered 保持兼容/验证用途；tools/maintenance 与可靠文本模式不能混用，工具范围见[契约矩阵](../contracts/pi-native-v1.md#可靠文本模式m58-15)。

回归使用真实 pi 1.4.0 SDK、仓库外合成账本和新 MCP 客户端，覆盖首个事件时完整答案尚未提交、reload 后重复命令重扫、取消后部分回放、存储中途失败、跨 delta 敏感内容、原始观察事件/partial 及错误诊断不泄露、provider length/error 不生成完整答案。headless SDK reload 不重发 session_start，旧 ctx 失效，重扫测试使用新命令回调而非旧 ctx。瞬时合成 provider 曾使首段回查追到已完成状态，新增固定输出节奏后再验证先后顺序；早期失败不作为通过证据。

新增计时使用 performance.now：首个非空 delta 到首个安全事件入队，以及包装 provider 调用到该入队。不是 provider 内部生成/网络/桌面绘制时间，首片可能因敏感尾部等待。
