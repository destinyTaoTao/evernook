# 页面指纹复核：常驻进程与 ACL 开销筛查

在仓库外隔离合成账本、已安装 Core 0.1.32 的同一独立服务上，分别用 8 次串行调用比较短命 CLI 与实验性常驻 Python 子进程。每次均重新读取并验证访问文件与服务端点权限；输入仅为单个合成时间线的 `fingerprints`，输出令牌没有写入日志。每次间隔 250 ms；进程树以 250 ms 采样，独立记忆服务未计入该树。

| 路径 | 8 次中位／最大墙钟耗时 | 被观察的树 private bytes 峰值 | 采样缺失 |
|---|---:|---:|---:|
| 每次启动 CLI | 969／1082 ms | 96.3 MiB | 0 |
| 常驻实验子进程 | 678／944 ms | 96.6 MiB | 1 次读取失败 |

两次峰值都包含实验驱动及瞬时 ACL 检查进程，不代表常驻子进程的独立空闲开销；样本少，不能计算正式 p95，也未测量长期驻留、并发、多页面、系统睡眠、CPU、审计写入和大库。实验 helper 只用于合成数据，未实现正式帧校验、进程退出联动、队列、公平性、请求取消或异常隔离，**没有接入 dsh 或作为生产 provider**。现有短命 CLI、权限检查及 12 秒租期均未改变。

另对同一隔离目录的 ACL 校验做 5 组微测：现有两次完整校验中位约 586 ms，将相同文件放在一次调用中约 296 ms。这只是定位调用开销；两种顺序在 ACL 变化竞争时不天然等价，不能据此删除第二次校验或缓存权限结果。需要先证明凭证及端点在打开、验证和使用期间的授权语义，再评估是否有安全且值得维护的优化。
