# #120 离线反思的 19 项失败与缺失归因

原先 33 例中，判断严格通过 14 例、失败 15 例、缺失 4 例。失败中有 **8 例在模型作答的那一轮已经给齐冻结答案要求的原文**。其中两例仅多了方位词“里”，另外有否定反转、混淆来源角色、答出示例中的无关值等实质性错误。另有三例实际搜索为零候选、一例缺少必要来源、一例最终判断被规则改写、两例涉及控制确认消息与决策协议。三个超时和一个未采场景保留缺失。

### 复算方法与边界

使用仓库外原始采集目录 `evernook-reflect-lifecycle-full-01`。每个 case 的 `*-workers/turn-N/stdin.bin` 保存独立请求，最后一条 user 消息包含实际问题和本轮证据。先前的演示消息含独立的示例答案和 ID，未计为用户证据。`stdout.bin` 保存原始响应，`details.json` 保存 Core 最终判断、引用、原文提交回执和 worker 尝试。32 次 Core 调用产生 38 次 worker 尝试，35 次返回状态 `ok`，3 次重试退出码为 1 且 stdout 为空。重试分发记录可以证明发送了材料，无法据此推断超时前模型执行到了哪一步。

诊断按提交回执把模型收到的消息 ID 映射回合成来源，核对问题、角色、发生时间、可用来源与引文，按轮检查冻结要求的引文是否完整送达；再独立重投影 Core 交付结果，复算原冻结评分器，核对 worker 输出与采集器回执。当前模型包没有状态／内容版本字段，最终交付引用的版本由原评分验证。检索和证据评分使用最终引用集合，不能直接代表模型各轮收到的材料。主要分组互斥；表中单列同一场景叠加的错误、表意差异及诊断限制。此次复查未生成新模型输出，不能据此估算换模型、改提示、增加候选后的增益。

在仓库根目录运行下列命令。输出 JSON 含逐轮发送的合成引文、原动作、逐字支持检查、格式反馈、冻结期望及实际交付结果。

### 固定提示、补回漏召的原文

再取四个原先漏召或少证的场景，保持原提示、问题、模型、预算和已有引文不变。逐一用同场景的回执和 SQLite 账本核对整条原文、来源 ID、角色与时间，只把原包缺少的来源追加到末尾。三次对鸟类记录的提问都对应同一个原始消息 ID。给模型的材料里没有冻结答案、评测标签或全库独立证据总数。两臂逐题交换执行顺序，原包的四次新判断与各自冻结首轮动作完全一致。

| 场景 | 原包 | 补齐原文后的首轮判断 | 与冻结要求的差距 |
|---|---|---|---|
| `old-initial` | 空包，弃答 | 答“青岚村”，逐字引用整条来源 | 只给地点，缺年份和拍摄对象 |
| `old-replay` | 空包，弃答 | 答“林夏在2019年拍摄过红嘴蓝鹊，这是七年前的经历。”，逐字引用同一来源 | 重述了年份和鸟种，漏了地点 |
| `old-continued` | 空包，弃答 | 答“2条”，仍只引同一来源 | 给出的数量缺乏支持。冻结账本有一次重复提交和一条独立原文 |
| `style-continued` | 只有默认偏好，答“简短回答” | 默认偏好和本次例外都在包里，首轮进入协议重试 | 没有捕获可评分的原动作。本轮没有执行重试 |

四次补证严格通过 0/4，其中三次产生有效但不符合冻结要求的动作，一次协议重试。漏召确实发生；即使把来源补齐，恢复正确答案还依赖对关系、时间、证据计数和输出协议的判断。对“独立证据共有几条”一问，单个有界证据包本身也不能证明库内完整计数。

四个原始搜索回执的查询 SHA-256 均与冻结问题一致，MiniLM 空间均为 ready。用同一配置重新编码这些问题，针对实际已存的 384 维来源向量计算精确 cosine。三条鸟类问题对唯一原文的分数分别为 0.140817、0.153461、0.232821。默认风格问题对偏好与例外的分数分别为 0.345244、0.245772。五个分数都低于语义候选阈值 0.4，原包仍经其他召回路径拿到了默认偏好。该定向实验没有评估放宽阈值后会增加多少无关候选，生产阈值维持 0.4。
