# M58-21：dsh 压缩与任务续接

对应 [#79](https://github.com/destinyTaoTao/evernook/issues/79)。新增有来源的核心任务检查点及原生 dsh 压缩协作，接口、限额和限制见[契约](../contracts/work-continuation-v1.md)。没有把核心扩成 harness，也没有把模型概括接纳为事实。

公开核心/stdio专项覆盖跨入口、重建运行实例、幂等、状态/输入限额、抑制/过期/废弃不回退、摘要依赖、独立 anchor、旧检查点消费和独立目标恢复。真实 SDK 新增8项，覆盖原生压缩与重载、辅助调用屏蔽/窗口、fork来源控制、最终计数中的抑制、8段长摘要/256-token配置及深入回源、两次局部压缩的依赖继承、用户换任务的低信任意图、原生配置自动触发对照。

双轴审查和自查实际复现并修复：独立 anchor 未参与读取检查；局部压缩额外消费的旧续接依赖丢失；遗漏定位元数据撑破额度；计数期间抑制后旧正文仍可派发；合法长会话名导致请求标识超长；空核心 payload 被当 JSON 解析；仅变更任务状态时控制 head 不变；capture-only 可借引用匹配差异猜测来源。保存入口现同时要求 capture+recall，且在任何来源/幂等回读前检查。每项使用公开接口或真实 SDK 先红后绿，未加入生产故障注入入口。

恢复现在认证并重放最新任务元数据，保留原文完整性门禁。首条请求明确标为 initial_user_request，演变意图和 Critical Context 保留为原摘要的受控引用；默认完成状态 unknown，不由合成回复“实现已保存”推断实际文件写入成功。
