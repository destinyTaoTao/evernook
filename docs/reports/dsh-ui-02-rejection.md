# DUI-2 — 同来源候选拒绝防重

Ticket: [#90](https://github.com/destinyTaoTao/evernook/issues/90), part of #88。

画像提案按类别、规范化标签和完整来源坐标/内容与状态版本匹配已有真实用户拒绝，忽略处理器、置信度、运行及候选ID。相同候选的新tag继承拒绝，不再成为待审草案；拒绝前已经生成的并行旧草案也不能事后确认。通用沉淀队列与页面待审列表过滤这些拒绝。原话保持可检索。

复用既有画像审查事件与用户批准绑定，没有第二份拒绝正文或新控制表，既有删除和恢复控制重放继续覆盖。主动重审通过新 `reopen` 动作绑定真实用户确认，须重开实际原始拒绝tag；后台 revise 不得自行重开。新来源证据仍可形成新草案。页面 rejected 视图只列原始拒绝，避免继承记录形成重复提示。

边界：这是确定性候选身份匹配，不是开放域同义判断；不同标签措辞/来源片段可形成不同候选。每类最多检查1000条用户拒绝，超过时明确失败，不能静默忽略旧决定。处理器改变候选含义需契约与评测，不自动扩大语义屏蔽范围。

验证：新增4项回归通过，覆盖跨实例/处理器/新tag、原话保留、并行旧草案、主动重审、新证据、归档控制重放后发布新运行库；此前画像及新拒绝测试8项通过（当时新测试为3项），沉淀17项通过，源码与新增测试严格mypy通过。没有浏览器或正式模型验收。
