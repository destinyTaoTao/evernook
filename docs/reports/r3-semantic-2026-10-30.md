# T15：本地语义召回与自适应近期范围

对应 [Issue #16](https://github.com/destinyTaoTao/evernook/issues/16)。基线 `ab17a5d`；前序 PR #31 尚未合并，本轮在其基础上单独提交。仅实现显式模型候选与合成数据验证，不启用日常数据、真实宿主、自动抽取或备份。

## 需求修正与交付

用户明确“最近七天只是一个维度，内容少时应追溯更长时间，并按内容量或时间调整”。实现不再将七天当作固定历史边界：

- `recent_days` 可指定 7、30、90 等实际时长；近期内容低于 `recent_target_chars` 时按来源时间向前扩展。目标以 Unicode code point 计量，不冒充最终 token 预算。
- 全历史精确、词法和语义候选始终保留。近期匹配不足时交还保留位置，不用无关内容凑数；时间未知/未来记录只走全历史路径，实际来源时间保持可见。
- 结果返回实际近期起点、扩展情况、累计字符与扫描上限。范围扩展最多检查 256 条记录；每个语义通道最多扫描 10000 片段，达到限制明确报告，不声称全库语义覆盖。

新增 `SemanticRecall` 同库可重建向量空间与批量维护。状态/内容版本及原文 code point 区间绑定片段；每批最多 16 个缺失片段，推理不持数据库事务，提交前复查来源。重复维护、进程中断和模型切换不会改写原文或混用向量空间。保护占位不入模型，显式更正/抑制在召回时重新过滤，无查询缓存。

首个 `LocalMiniLM` 适配器复用已准备的固定 R0 候选（384 维 q8、固定 revision 和文件 SHA-256），使用 Node 24.x / Transformers.js 4.2.0 / onnxruntime-node 1.24.3。无请求期下载或云端 fallback；核心/无模型路径仍只有 Python 标准库。Node worker 拒绝 fetch/socket，成功响应必须为零次尝试；未变更 OS 网络或证明原生组件经过系统隔离。

CLI 增加 `recall/refresh-semantic/semantic-status`；MCP 增加只读 `evernook_v1_recall` 与 `status.semantic`，可信启动端才可提供模型配置。默认查询模式七项、完整模式十一项，原有写操作限制继续有效。实际 API、参数、降级与安装边界见[语义契约](../contracts/semantic-v1.md)，可复现实际模型验证见 [probes/semantic](../../probes/semantic/README.md)。

环境沿用 Windows 固定 NTFS、Python 3.14.4、SQLite 3.50.4、Node 24.11.1，i7-10700/约 32GB、CPU 推理；未使用原提案中的 RTX 4070。源数据、模型、访问文件、数据库、原始输出与构建物都位于 checkout 外；日志目录为 `E:\evernook-lab\r3-semantic-20261030`。

- 完整契约回归 103 项全部通过，742.108 秒（`tests-full.txt`）。完整运行期间另发现元数据损坏降级缺口；新增回归先失败，再修复并定向跑最终语义 11 项全部通过，38.929 秒（`tests-semantic-final.txt`）。当前 104 项均有通过覆盖，未声称在最终增量之后额外重跑完整 104 项。
- 严格 mypy 检查 29 个源码/测试文件通过；Node worker 语法检查通过。崩溃回归覆盖向量提交前/后的真实进程退出和原文不丢失；不代表物理断电验收。
- 真实本地候选在三条普通合成记录和一条保护投影上建索引；“饮食偏好”命中“喜欢吃辣”，“上下班交通方式”命中骑自行车记录，精确查询命中原文，逐段坐标一致。单条合成无答案查询返回零候选，不能推广为开放世界零误召回。
- 真实 CLI 与 stdio MCP 使用同一索引返回正确来源；实际 Node 子进程超时及缺模型均保留字面证据与明确原因。完整输入、来源、候选、耗时和降级结果保存在外部 `real-run-01/results.json`。
- 成功构建 wheel 并确认包含 worker；未安装 MCP 的独立环境通过安装后 CLI 语义查询。带语义派生表的普通归档实际导出/恢复成功，恢复仍为 `review_required`。
- 最后状态降级修复后，真实模型/CLI/MCP/超时及缺模型探针另行复验通过（`real-run-final/results.json`）；最终 wheel 重建并在无 MCP 环境再次通过安装后语义查询。

首轮四个实际查询各包含新 Node 子进程/模型载入，耗时约 2.15–2.68 秒；三条普通记录的初始索引约 2.30 秒。这不是 p95、规模基准或冷 OS 缓存测量，**没有达到约 1 秒的完整召回目标**。本轮没有为此增加常驻服务；后续需在既定质量/资源门槛下测量模型复用、索引和服务开销，不能把小样本能力验证算成正式验收。

## 对抗式自审

检查了部分消息分块续建、不同模型空间、来源变更/抑制与计算并发、保护投影、敏感查询、无穷/NaN/零向量、令牌错误、模型超时/缺失、未知/未来时间和稀疏/密集近期数据。模型输出只影响候选排序，不产生事实、人设或工具权限；跨次查询没有可复活旧证据的结果缓存。

自审复现：语义元数据缺列时，原状态查询抛 `storage_unavailable`，导致可用的字面回取也失败。最小修复将该派生状态报告为 `unavailable`，计数未知时为 `null` 并附固定错误码；新回归验证字面证据继续返回。未更改核心账本异常、持久化强度或源事件契约。

这是主代理自审，不声明独立代理审查。T15 保持开放：最终 embedding/许可准入、正式中文质量、OS 断网、规模向量查询与约 1 秒门槛仍未验收。自动事实接纳/时态、最终上下文预算、日常 dsh 自动采集注入、保险库及备份继续各自门禁；本轮不解除 T13/T16 或宣称完整记忆模块已完成。
