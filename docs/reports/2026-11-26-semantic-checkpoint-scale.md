# 百万条语义覆盖的增量检查点对照

Windows、Python 3.14.4、SQLite 3.50.4。在 1,000,000 条合成来源、1,000,000 个 384 维向量、零待补来源的账本副本上，公开 `SemanticRecall.status` 五对热样本中位数由 2.510 秒降至 0.016 秒。语义空间、索引总数、失败数和来源水位逐字段一致。三类完整召回均有两对结果，所有候选、顺序、引用、相似度和降级字段一致。最快的一次完整召回仍需 3.892 秒。

## 构建和测量边界

从[语义分块覆盖索引对照](2026-11-22-semantic-coverage-index.md)的启用侧取合成夹具，检查源库没有待写 WAL，将数据库复制至新的私有临时目录后核对 SHA-256。副本已有来源、时间、分块覆盖索引和有效的词法覆盖检查点。在维护身份下执行 `configure_coverage_checkpoint(enabled=True)`，耗时 23.053 秒，主库文件增加 161,857,536 字节（约 154.4 MiB）。构建前后公开状态相同，构建后词法检查点仍有效。

在同一副本、同一进程上交错运行两侧，消除物理布局与配置差异。基线通过 `patch.object(semantic_checkpoint, "status", return_value=None)` 选择原有全量状态查询，启用侧按正常入口选择已构建检查点。计时包含公开入口的身份校验和审计。两侧各进行一次不计分状态预热，随后五轮状态样本交替改变先后次序。

| 公开状态 | 五个样本（秒） | 中位数（秒） |
| --- | --- | ---: |
| 原全量统计 | 2.177、2.510、2.173、2.671、3.107 | 2.510 |
| 检查点 | 0.012、0.016、0.015、0.019、0.022 | 0.016 |

采用 `SyntheticFingerprints`、`as_of=2026-11-04T00:00:00Z`、`limit=10` 和 120 秒超时。完整召回的两轮对调先后次序，每次返回 10 个候选且无降级。整页 SHA-256 也与上一次分块覆盖索引对照的三个公开摘要相符。

| 完整召回 | 原全量统计（秒） | 检查点（秒） |
| --- | --- | --- |
| 近期 `合成条目0999999` | 13.191、8.562 | 9.477、8.470 |
| 历史 `合成条目0000001` | 11.251、12.229 | 6.841、9.521 |
| 历史查询，限 2021-01-02 UTC 单日 | 8.238、5.866 | 3.892、4.444 |

本次保留操作系统缓存，同机另有工程验证任务。每组两对完整查询仅报告原始样本。真实模型、混合读写尾延迟、检查点的长期写入成本和每日使用仍需独立验收。

## 正确性与复现

正常读取最多复核 100 个变动 ID，超过上限时全量查询。对已经追平的库，合成测试用 SQLite authorizer 禁止访问来源、可见性、采集、文档、分块及失败表，仍正确报告覆盖状态和物理向量数。独立测试覆盖两种向量空间、多个分块部分覆盖、版本更动、失败分块、隐藏或孤立来源保留的向量、读写快照、旧库缺表、缓存或队列改写、重建中断、归档和彻底删除。[语义检查点契约测试](../../tests/contracts/test_semantic_checkpoint.py) · [维护命令与边界](../contracts/semantic-v1.md#可选语义覆盖检查点)

规模复现可使用前述百万合成库、相同的三个查询和检查点开关。逐次计时使用 `time.perf_counter()`，逐字段比较 `SemanticStatus` 及 `RecallPage`。本机本轮脚本及完整样本在临时目录 `evernook-semantic-checkpoint-final-69659a280b424044aae3c8565a6c786f` 中的 `run.py` 与 `samples.json`。

另在独立的合成小库激活服务，以真实 CLI 子进程完成准备、限量刷新、重建和移除。只读身份被拒绝，MCP 工具不可见，CLI 与 RPC 均拒收调用方指定的模型配置。服务绑定配置变更后准备与刷新返回 `embedding_config_changed`，维护身份仍可移除检查点。百万库计时使用 Python 公开入口，未包含服务传输。[独立服务契约测试](../../tests/contracts/test_service.py)
