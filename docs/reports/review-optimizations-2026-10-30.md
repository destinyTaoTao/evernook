# 外部审查核验与接入优化

对应 [Issue #30](https://github.com/destinyTaoTao/evernook/issues/30)。基线 `117740e`，仅根据当前源码、契约和已有确认决定核验两份审查意见；下述实现不代表正式宿主接入、保险库或记忆质量验收。

## 采纳判断

| 意见 | 核验与处理 |
|---|---|
| 目前主要是可靠证据账本，产品闭环未完成 | 属实。自动采集/注入、真实抽取模型、语义/近期/预算上下文、保险库仍有缺口；不以已有契约测试替代宿主和质量验收。 |
| 缺少 CLI，接入必须编写 Python | 属实，本轮实现薄 CLI。核心/CLI 无第三方依赖，复用原有鉴权、幂等、敏感分流和可见性过滤。 |
| MCP 客户端认证不能证明用户角色和管理意图 | 属实，本轮默认收敛为六个查询工具。写入、标重要、更正/抑制和全量列表只在可信启动端显式选择 `trusted-host` 时开放。 |
| Python 3.14 只是随意设置，应直接放宽到 3.11 | 未采纳直接修改。[ADR-0003](../adr/0003-r0-evidence-ledger-and-retrieval-reuse.md)与 [R1 契约](../contracts/r1-memory-v1.md)已有明确首验基线；代码看似兼容不代表依赖、SQLite、ACL、崩溃恢复和完整协议在旧版本已验证。 |
| 正则可能漏检，当前凭证不能恢复 | 属实。现有 `Event.sensitive/protected_source` 已能独立于正则强制投影，不是只有自动检测。回执明确 `original_saved=false`，不是加密成功；本轮补齐 CLI 与接入说明，不把扩大正则当作保险库。 |
| 应先补历史明文治理与加密 | 方向合理，但涉及真实销毁、派生内容、WAL/备份及恢复材料，沿用 [T19 #20](https://github.com/destinyTaoTao/evernook/issues/20)、[T22–24 #23–25](https://github.com/destinyTaoTao/evernook/issues/23) 的确认与准入，不实现一个只隐藏当前行的伪清理工具。 |
| 共享记忆应按项目/用途隔离 | 不能作为既定缺陷直接改。当前确认的是跨入口共享普通记忆；本轮限制默认操作权限，保留内容共享。用途/敏感等级和普通重要记忆加密需要独立产品决策。 |
| Skill 基本免费，可以解决自动注入 | Skill 可提供调用提示，但不能保证模型调用、真实来源、用户授权、可靠采集或每轮注入。本轮不以 Skill 代替真实宿主闭环。 |
| 必须先新增常驻服务 | 尚无当前争用故障或性能证据支持立即引入。多个实例可复用同一 SQLite；规模、重建及并发竞争需要按 [T21 #22](https://github.com/destinyTaoTao/evernook/issues/22) 测量，模型准入后再评估进程共享成本。 |
| p95、召回质量及十万/百万规模未验收 | 属实，不把单元/契约测试耗时或 R0 小样本作为性能结论。 |

## 实际改动

- 新增 `evernook` / `python -m evernook.cli`：初始化、配对、保存、检索、按 ID 回取、状态和分批词法维护。文本/查询通过有界严格 UTF-8 JSON stdin；令牌只读私有访问文件，错误只返回固定码。
- MCP 默认 `recall` 使用显式六工具允许列表；未开放操作直接调用也被拒绝。`trusted-host` 保留完整十项；模式只能来自可信本地启动配置，不能从工具参数提权。状态分别报告适配器模式与核心能力。
- 增加五项 CLI 外部行为回归、一项真实 stdio 权限回归；既有完整模式协议测试显式选择 `trusted-host`。
- 补齐 [CLI 契约](../contracts/cli-v1.md)、[MCP 迁移与信任边界](../contracts/mcp-v1.md)及实现地图；不修改已有需求/设计工作区改动。

**兼容性变更：已有需要保存、更正、标重要或列表的 MCP 启动配置必须显式加 `--profile trusted-host`。** 这并不证明该宿主事件可信；宿主还必须把角色/来源和用户管理交互置于模型控制之外。默认查询仍能读取共享普通记忆，不是项目隔离或防遍历方案。CLI 也属于可信维护操作，不能把 unrestricted shell 当作查询模式的安全替代。

## 验证

验证环境：Windows 固定 NTFS、Python 3.14.4、SQLite 3.50.4；完整回归沿用仓库外开发环境。原始测试输出位于 `E:\evernook-lab\review-optimizations-20261030`，运行库/访问文件均为 checkout 外临时合成数据。

- 严格 `python -m mypy`：26 个源码/测试文件通过。
- 独立核心环境仅安装 `evernook==0.1.0`，确认未安装 `mcp`；安装后的真实 `evernook.exe` 完成初始化、保存、读取，Unicode/CRLF 原文一致。
- 完整契约运行 93 项、836.564 秒：92 项通过，一项新增 CLI 测试将普通抑制回取的错误码误写成 `not_recallable`，实际沿用既有普通读取/MCP 语义为 `message_not_found`。仅修正该测试断言，定向复验 1 项通过、24.803 秒（`tests-cli-suppression-final.txt`）。93 项均有通过覆盖，不声称最终源码另跑了一遍完整绿灯套件。
- 测试耗时包含 ACL 与真实子进程，不是接口延迟或规模性能测量；不能将缺少可选依赖导致的导入失败统计为通过。

## 对抗式自审与剩余边界

检查了默认隐藏工具的直接调用、工具参数提权、未来新增操作的默认暴露、角色伪造边界、未知/重复 JSON 键、非法 UTF-8、输入大小、幂等重试/冲突、已抑制数据回取、敏感投影与错误回显。默认过滤采用显式允许列表，避免以后新增操作自动获得默认权限。新增代码不改变数据库格式、事务/持久化强度、原文或既有来源规则。

这是主代理自审，不声明独立代理审查。没有下载模型、启用保险库或备份、注册真实宿主、处理私人数据、执行彻底删除或运行规模/延迟基准。真实 dsh 自动存取仍按 [T10 #11](https://github.com/destinyTaoTao/evernook/issues/11) 及其现有依赖推进；语义、时间区/上下文预算和保险库准入继续保留，不以本轮入口可用替代完整记忆产品验收。
