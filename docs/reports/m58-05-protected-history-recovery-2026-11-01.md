# M58-05 / #63 敏感历史后的安全恢复

## 实现与披露

真实 dsh/pi SDK 回归复现：敏感用户输入保存为投影后，扫描在同一记录抛错，后续安全输入不能调用 provider。现在保留投影回执并完成扫描；当前敏感输入依然阻止发送，后续完整保存的安全输入可恢复。

恢复采取保守范围：排除当前安全用户消息之前的非系统原生历史，保留固定系统上下文及当前安全回合；无法定位边界、保留字段仍含已知受保护原文时阻止发送。最终检查包含消息正文、系统 sections、工具声明和重放元数据的序列化字段与拼接文本；dsh 还检查完整请求字段。没有绕过既有保存、保护和输出发布屏障，也没有改写宿主原始历史。

dsh 返回 `status(sessionId)`：最新回执、累计 capture_gaps、受保护原件未保存状态、实际历史省略数量和 `current_safe_turn_only` 范围。Pi 用通知及证据元数据区分投影已保存、原件未保存与安全恢复；重装/重扫从原生记录重新建立状态。普通账本不保存被保护原件，宿主原始副本仍属宿主残留。

dsh 0.2.1-rc.3 冻结 loop 请求；需要过滤时通过公开 one-shot stream 发送筛选副本，由外层原屏障保存后发布。该路径会重新解析 provider 注册；固定 SDK/profile 测试通过，执行中替换 adapter/HMR 的兼容性未验收，日常准入不得据此放行。Pi 1.4.0 使用 context 及最终 provider transcript 两次检查。
