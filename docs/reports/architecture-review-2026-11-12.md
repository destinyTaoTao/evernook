# EverNook 基础架构审查与重构方案

2026-11-12。面向 dsh 的单用户、本机离线、跨入口共享记忆系统。部署与隐私范围已由用户确认；以下接口形态、切换步骤、检索选型和验收分解为实施提案。

## 结论与审查基线

证据账本、逐字回取、事实时态、用户控制和 dsh 安装预览已经有实现。要让个人助理多年后仍能回答问题，尚缺四项端到端能力：共享服务在宿主退出后继续维护，按语义找回分布在全历史中的证据，画像变化真正影响下一次宿主请求，以及原机丢失后恢复可用的记忆。凭证保险库还有独立的私密输入、销毁和恢复要求。按目标重构服务边界，保留现有核心与持久化语义。

## 服务与数据归属

沿用 Python Core、SQLite 权威账本、可重建索引与离线 worker。每个已打开的账本只接受同一服务管理的写入。前台提交、用户控制与后台发布复用现有事务与回执。dsh 负责会话、模型、工具、用户页面和可靠发布；服务负责记忆、派生任务、授权与恢复。模型只接触获准的普通读取操作，维护身份和保险库明文操作分别隔离。[运行形态决定](../adr/0013-host-independent-memory-runtime.md)

| 面向谁 | 建议的能力契约 | 成功的含义 |
|---|---|---|
| 宿主自动采集 | 存事件与流。带入口/会话/分支、来源事件 ID、角色、发生时间、完成状态、输入隐私等级与可用材料 | 返回稳定回执，分列普通证据、投影、受保护原件与材料状态。收到完整回执才允许宿主发布依赖该证据的结果；重复投递返回同一结果，冲突报错。 |
| 宿主每轮注入 | 取上下文。带当前输入回执、意图或检索短句、参考时间、预算、截止时间 | 回传版本化的已确认人设、精选画像、近期进展和相关长时证据，并列来源、遗漏、覆盖和降级。按回执排除本轮输入。宿主固定系统规则控制如何使用证据，历史话语进入低信任数据区。 |
| 用户或明确查询工具 | 查来源、逐字分页、关键词/语义、时间和事实版本；支持 normal/deep | 结果可追溯到来源、片段及版本。超时或索引落后返回已验证的部分和未搜索范围，避免把“暂未查全”表述为“从未发生”。 |
| 可信用户操作 | 更正、移出画像、抑制来源、裁决冲突、恢复和彻底删除 | 预览受影响对象；确认绑定目标、来源版本与操作。每次提交复核水位。普通模型身份不能把一段旧对话变成用户的新授权。 |

现有 MCP 工具、可信 CLI 与管理页可以继续作为协议客户端，出入参按旧契约映射。正式运行时由服务拥有库路径和调度租约。Windows 首选待验证的用户级本机 IPC（如命名管道），重点验证 ACL、配对身份、消息上限、超时和取消；传输选型可由实现者据实验决定。原始数据与密钥继续存放在 checkout 外。普通服务持有锁定收件所需的写入材料，解密能力留给可信本地辅助程序。

### 一次切换与回滚

推荐复用现有算法和存储，一次切换服务、接口和已启用客户端。开发阶段可用合成副本、只读影子比对和兼容测试；正式环境设单一写入权。分批上线多个长期并存的写入路径会使删除、更正和队列水位难以归属。整套替换为外部框架还会增加既有证据、权限、恢复和流式语义的重新验证成本。

1. 先冻结旧入口的回执、可见性、更正、流式、取消、审计和恢复契约。在同一组真实版本的 dsh 与 CLI 上跑新服务客户端，并核验普通/维护身份分离。预览配置现在只检查普通权限是否超出白名单，缺 `capture` 的只读身份可能通过安装检查；新版本启动就要报告缺失权限。[安装校验](../../plugins/harnesses/src/dsh-web.ts)
2. 排空在途请求和流，暂停工作租约，持久化检查点并核验普通备份。清点所有启用的入口、自动启动项、直接写库工具，以及切换会触及的受保护原件与密钥。若已有原件，切换前在隔离环境演练失败后仍可经授权解密、未授权不可读；可保留原存储与密钥路径，或使用用户已选入的独立恢复材料。普通备份无法完成这项验证，无须为切换强制导出保险库。现存资产保全验证失败时保留旧运行环境。先停止旧写入方，再由服务接管；若旧程序仍可直接访问库，须通过阻止其启动或隔离旧库路径落实单一写入。仅在新版写入方均就绪后恢复提交。
3. 验证主机关闭 dsh 后队列仍推进；重启中断后不丢已确认事件、不重复发布画像。模拟未升级的旧入口，须明确拒绝或走兼容客户端。不得让旧插件悄悄另建一个账本。
4. 切换前失败可回到冻结的旧配置；新服务接收过写入后，应保留当前库和新回执，优先前滚修复。只有已证明旧版本兼容当前库和所有控制水位，或已验证反向迁移，才可回退。切回旧快照会丢失新记忆和撤销决定。

## 分层与后台处理

| 层 | 权威内容与更新方式 |
|---|---|
| 原始证据 | 追加聊天、工具、附件/缺口与受保护引用。发生时间与收到时间分别保留。更正附新证据，旧原文可按控制策略审查。 |
| 工作与近期记忆 | 最近交流、任务进展、重要交代走同步读取。显式记住、更正、抑制一经提交，下次读取立即生效。会话摘要附来源范围、覆盖水位和任务完成状态。 |
| 长期事实、经历、画像 | 证据片段 → 候选 → 风险及冲突判断 → 有版本的事实/画像。区分用户自述、引用、助手猜测与用户确认。事实区别“当时就说错了”和“后来变了”。低风险白名单逐类准入，冲突期间暂停确定性注入。 |
| 核心人设和经验 | 核心人设独立版本化并经用户确认；一般经验可从多条有来源经历形成草案。用户可以追问形成依据。人设正文的修改不由定时任务自动提交。 |
| 导航与索引 | FTS、带跨度的向量、日周/主题摘要及界面关系均可从有权限的证据与控制记录重建。摘要记录引用范围；删除或抑制来源后，对所有派生层重新验证可见性。 |

复用已有 SQLite 待处理表、调度进度与租约。后台分别维护词法、向量、摘要、画像的进度和最老积压时间；按来源版本与处理器版本幂等发布，同事务复核来源仍有效。错误分可重试、需人工及确定性跳过，保留原因。前台活动、资源预算和暂停操作能让工作在批次边界让行。现有检查点触发器会影响原文事务，启用成本须体现在真实写入与故障验收中。[调度契约](../contracts/host-consolidation-v1.md) · [可选检查点 ADR](../adr/0012-optional-lexical-coverage-checkpoint.md)

优先扩展两个有区分度的场景。其一，长对话中“我一般喜欢短回答，但这次展开讲”应形成长期偏好和本轮例外，各自有来源；其二，跨两次会话的共同经历可生成事件摘要，引用两次会话的证据，资料不足时保留空缺。统计每类命中、误接纳、漏提议、争议和用户修订；不能用待审数增长衡量自维护效果。

## 多年召回与 dashboard

对“当年在湿地最常观察什么鸟”分别测试有原话、仅同义问法、时间范围变化、同名干扰、证据已抑制和根本没说过。把正确证据放到语义扫描前、中、后三段，使用近期窗口外的来源。先测候选 Recall@10，再测是否被装进最终请求、引用能否逐字回取、宿主是否按时间和证据作答。对长输入提供独立检索意图/显式深查，保留原始问题。近期和全历史各保留候选机会，精确重要交代始终能直接回取。

第一轮与原扫描路径做同夹具对照，比较按时间/事件缩小范围、离线全库向量候选索引两条路径。选型看跨年召回率、建库时间、p95、峰值与删除/重建代价；限定时间搜索无法覆盖用户忘了年份的情形。新增向量组件须作为可重建派生资产，绑定模型/切片版本，只返回候选 ID 和跨度，最后按权威账本重验。模型或索引故障时保留原话/字面路径并展示降级。

dsh 保留已有面板，优先让用户回答三件事：**为什么记住这个、哪一轮用了它、怎么修正它**。由一条画像或事实展开一至两跳的来源、版本、替代及依赖关系，节点可点进原话，按时间和会话筛选，抑制后只展示允许的元数据。侧栏按入口、会话及适用分支过滤；当前 Web 侧栏只传 session ID，若不同入口复用同一 ID，显示范围会混淆。诊断视图展示每层水位、最老积压、召回依据、遗漏与实际预算模式。图形和列表复用同一个只读查询与控制策略。[侧栏实现](../../plugins/dsh/client.js) · [管理读取](../../src/evernook/management.py)

配置由服务校验、版本化，dsh 展示有效值及生效范围。用户可调近期窗口、上下文额度、后台批量/时段、白名单和私密默认行为。防越权、私密正文禁止普通索引和提示、核心人设修改须确认等不变量由契约约束。Web 真实请求 token 预算沿用等待 dsh 原生完整计数接口的决定；当前可显示字符兼容与缺失能力。[预算工作项 #105](https://github.com/destinyTaoTao/evernook/issues/105)

## 私密输入、快速销毁与异机恢复

私密标记必须先于普通宿主转录、日志和模型请求。若 dsh 没有可验证的输入前拦截，插件从会话中唤起可信本地输入界面，让用户把秘密直接交给 EverNook；dsh 只收到安全回执。整段模式的起止须清晰，附件、流和取消有各自的保存状态。普通入口的凭证检测是补救路径，自然语言秘密依靠用户显式标记。遗留普通记录后来标密涉及历史派生清理、备份与宿主副本，是另一项操作。[已确认私密范围](../adr/0014-private-capture-and-local-vault-destruction.md)

本地解密沿用独立主口令、对象和用途绑定；逐次授权与一次性消费要覆盖版本更换、锁屏和并发。销毁助记词与解锁/恢复材料分离，登记与执行只在本地可信界面完成。实现前盘点设备密钥、密文、恢复包临时副本、缓存及尚有效的授权；销毁过程中冻结新受保护写入和解密，并可在崩溃后继续。成功回执以本机再也不能用留存材料解密为准，独立备份或已交付正文仍可能存在。介质物理擦除与抵御同账户恶意进程超出现有保证。

异机恢复需要可选的加密普通备份、另行选入的受保护原件及独立保管的恢复材料。认证清单记录证据/控制水位、资产范围、版本与备份时间。原机完全不可用时先进入审查模式，验证完整性并应用持有的最新撤销/抑制记录。只有旧备份时，展示最后可证时间、可恢复条数和缺失的后续控制；用户已选择允许在可信入口一次确认开放整份普通备份。该确认绑定具体备份和控制水位，只开放已知控制允许召回的内容。备份后被删除但缺乏删除记录的内容可能重新出现，确认前应明确说明。保险库另行解锁，客户端重新配对。验收包括已知抑制持续生效、未经确认不进入普通召回、重复确认幂等、本机销毁后独立备份可恢复、恢复材料缺失时无法解密。[现有恢复发布](../contracts/runtime-restore-v1.md) · [现有删除边界](../contracts/purge-v1.md)

| [Letta](https://docs.letta.com/v1-sdk/memory/memory-blocks) | 有大小限制的 persona/human 常驻块，支持只读。 | 将已确认人设、精选画像和按需历史分别计预算，返回修订版本。画像证据和写权限留在 EverNook。 |
| [Hindsight](https://github.com/vectorize-io/hindsight#core-concepts) | 服务端记忆接口，语义、关键词、关系、时间多路召回，观察关联证据。 | 用独立评测比较各通道在跨年与纯同义场景的增益；延用 dsh 负责最终对话回答的分工。 |

## 交付顺序与准入

1. **建立切换前基线。** 固定当前主线/预览产物、客户端、夹具和冻结 policy。给每一项记录 Core、SDK、安装 Web、真实模型四个证据层次。补测长输入、跨年无词面重合、同会话 ID 跨入口、只有 recall 的普通身份与前台写入同时重建。
2. **在隔离环境完成统一服务与全部接口，然后一次切换。** 验收 dsh 开闭、其他已配对入口、服务重启、重投、维护让行、旧写入方拒绝、前后水位及回滚条件。首次端到端场景从页面确认偏好开始，经新会话实际 provider 请求、用户更正、下一轮引用及来源抑制，逐步检查。维护页面动作不进入模型工具。
3. **完成日用质量闭环。** 单项定位跨年候选、上下文预算、自动接受/澄清/拒绝与回答；失败留样。近期、历史、无答案、热门查询分别在空闲、持续写入和重建下验证。沿用冻结标准：独立 10 万/100 万数据集、完整记忆 p95 ≤1 秒、热候选融合回源 p95 ≤150 ms、近期词法 p95 ≤50 ms、质量分项按 policy、阻断项为零。候选版本需自行通过，不能继承旧包长跑。[冻结策略](../../probes/admission/policy.json)
4. **独立验收私密和恢复。** 用合成哨兵覆盖私密输入到宿主历史、普通库、向量/摘要、审计、导出及备份。锁定仍可加密保存；未验证无明文；销毁中断可继续；原机全部不可用时仅凭独立材料恢复到声明水位。该能力通过前，界面须明确可用范围。

以上顺序用于开发和隔离演练。统一接口可以先完成；日常 profile 的实际切换需等对应质量、性能和安装门槛通过，且已存在的普通及受保护资产均可保全。新保险库功能的验收不应掩盖既有资产的迁移风险。

本轮只改领域文档和提案。实际运行现有 `test_context_companion`、`test_preference_clarifications`、`test_purge` 三组本地合成契约测试，32 项通过。上述大规模、模型、安装和性能数据来自相应版本的既有记录。本轮没有重新执行规模评测、真实宿主、掉电或销毁试验。

## Hindsight 研究后的设计增量

2026-11-12 后续用户要求深入借鉴沉淀、反思和推理。已按固定源码研究，详见 [研究报告](hindsight-design-review-2026-11-12.md)，并同步总 spec #106 和 #112–#114。

分开四种过程：原始证据抽取事实与经历，跨证据形成综合观察，按用户定义问题刷新主题认知视图，显式深入查询执行有预算的检索推理。后三者分别由 #118、#119、#120 交付，#121先冻结专项夹具。综合观察保留支持和反证，视图依赖新证据和撤销控制共同失效，查询时推理结果默认临时。dsh负责最后对话与工具动作。

近期工作继续优先 #107–#111 独立服务与dsh闭环。新增层次复用账本、任务与来源控制，普通每轮读取有效有界资产，深入推理单列预算与准入。完整验收同时比较原始召回、加观察、加视图、加反思的增益及成本。
