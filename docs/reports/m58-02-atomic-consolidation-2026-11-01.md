# M58-02 / #60 完整沉淀与故障恢复

## 实现

补齐旧测试的最终队列断言后复现：候选成功后的异常可以使调度器记录已处理，却没有可读草案。

候选完成、画像状态转换、全部审查草案和包含预期草案 ID 的完成标记现在共用一个 SQLite 短写事务。复用原模块的事务内校验，不新增服务或通用事务框架。提交前再次检查租约；任何阶段失败均回滚整批，处理进度只在完整资产成功后写入。

恢复读取不再把任意一项草案当作完成。首次完整结果及档位保持权威；稳定 ID 和同一事务防止重复资产。旧版本留下的候选成功/资产缺失任务，可以由原维护身份重新生成草案，核对当前来源和已提交候选哈希后原子补齐。生成内容不匹配时明确 `candidate_result_conflict`，不推进进度；不能从已丢失的草案元数据推断当时模型输出，需提供匹配的处理器/原草案。公开普通候选完成入口仍要求有效 token，恢复不扩大普通采集或模型权限。

删除候选运行时先清理新增完成标记的外键引用。旧部分队列显式重试保留已有项并补齐缺项。
