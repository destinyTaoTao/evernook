# M58-10：pi 核心预算与双入口共享

Issue #68 在 pi 专用 provider 的最终委托边界复用 #67 的同一核心、保存策略和本地 tokenizer。完整记忆 payload 独立复算，宿主请求与预留输出受配置和实际目标模型窗口共同约束；非法配置、超限和取消在派发前阻断，状态提供明确错误码。注入为临时用户数据，不变成新的原始用户证据或管理权限。

两个入口各用独立 `capture/recall` 身份。真实 dsh→pi、pi→dsh 跨会话 SDK 测试核对最新来源可用、分支身份和重复重扫幂等；不另复制事实、画像或可见性过滤。保存策略逐次读取，推荐/保存/实际状态分别可查询。AbortSignal 经 MCP 取消通知传入核心协作事件，取消正在进行的本地计数时杀死并回收子进程；输入已提交的事实不被取消伪装成未保存。

对抗审查复现了其他扩展在采集后插入图片的最终边界绕过，现最终 transcript 统一拒绝图片。预算模式还在安装和请求阶段拒绝会在计数后切换物理路由的 `pi-virtual`。两项真实 SDK 负例均通过。

验证：dsh/pi 完整原生套件 26 项通过（53.87 秒）；MCP 15 项、tokenizer 4 项（包括实际计数子进程取消回收）通过；源码及相关测试严格类型检查、TypeScript 检查和构建通过。审查两路均完成，发现的问题已修复。

测试采用真正本地 WordLevel tokenizer 与合成 provider，不冒充真实部署的模型模板、日常 profile 或多模态预算验收。宿主仍需提供对应 provider 的可靠 framing counter。此增量保持整段保存后发布，不等于可靠分块流式；SQLite/ACL 仍有自身时限，也不声称硬实时取消。全量测试类型检查中既有沉淀测试的 3 条 unused-ignore 由后续相关票据处理。
