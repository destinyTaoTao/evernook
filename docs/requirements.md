# 需求与边界

状态：修订版需求与设计基线已由用户确认，尚未实现。日期：2026-10-29。

## 已明确的产品目标

1. 作为外挂记忆模块接入 dsh、pi、桌宠等入口，自动保存交流并提供相关上下文，跨多轮与跨会话保持连续性。
2. 交代的重要事情应能逐字回取，不能只保留概括后的意思。
3. 保留多年的交流信息，并支持归纳、总结、更正与更新。
4. 召回要快且准确，最近一周的事情更容易、更快获取。
5. 记忆存储与全部处理离线运行，禁止记忆组件失败后自动转云端；其他端调用记忆服务，聊天由调用端负责。
6. 同一个 AI 在多个入口默认共享全部记忆；dsh 优先，再接 pi 与桌宠。
7. 全量追加保存可获得的交流、工具事件和附件，分类不改原文；可选加密保存含凭证原件，普通记忆使用脱敏投影，未采集部分明确记录缺口。
8. 有来源且无歧义的信息可主动沉淀与更正；经验可自动总结，执行规则与核心人设变更仍经用户确认。
9. 凭证读取独立于普通记忆共享：主口令在本地界面输入，明文默认本地展示；交给指定 harness 需按次授权。锁定时可加密写入，读取必须验证。
10. 项目采用清晰的模块组织和少量稳定接口，关键能力配置化；安全授权不可被普通配置或模型参数绕过，性能与维护成本通过实际验证约束。

## 初始工作假设

单用户、独立于交流入口；首个部署目标为用户指定的 32GB 内存、13600K、RTX 4070。记忆存储、embedding、抽取、重排和沉淀已确认为本地离线；Python 为当前建议，具体模型和目标操作系统待验证。首版捕获入口可提供的文本、工具事件和附件原件，多模态理解另行评估；转写准确率不能由记忆层保证。

## “不遗忘”的工程定义

| 目标 | 可承诺的系统行为 | 不应混淆的能力 |
|---|---|---|
| 原文保存 | 对已确认提交的数据，支持按 ID/来源完整读取、导出与恢复验证 | 磁盘、文件系统或备份也可能失败，不能说写入永不失败 |
| 重要交代 | 明确标记后保存完整原文与版本，支持指定条目确定性回取 | 自然语言模型不能保证总能识别所有隐含的重要性 |
| 问答记忆 | 返回相关来源、时间与状态；证据不足时不编造 | 任意自然语言问题永远 100% 准确不属于可无条件保证的目标 |
| 自我沉淀 | 从来源形成候选事实与摘要；可审查、修订、回滚和重建 | 不等于自动训练模型权重或自动改变人格 |

## 业务不变量

- 消息是证据源，索引、事实和摘要均为派生数据。自动整理不能覆盖或压缩掉唯一原文。
- “已记下”只在持久化成功后返回；失败必须让调用方知道，不得静默降为内存保存。
- 写入有稳定的幂等键，重试不得产生重复消息或重复任务。
- 用户真实陈述、助手回复、引用材料、角色扮演和提炼推断分别标识。助手自行生成的内容不能自动升级为用户事实。
- 每条派生事实关联一个或多个来源及原文位置；摘要不是事实存在的唯一证据。
- 更正不自动等于时间变化：“我刚才说错了”和“我现在改了”需要不同处理。不明确则保留冲突、请求澄清，不静默覆盖。
- 最近七天属于召回优化，超过七天不自动删除、不自动失效。时间优先不能取代相关性与事实有效性。
- 原则上不自动删除原文；用户主动要求遗忘或删除时，删除语义必须覆盖派生索引、缓存、导出和备份策略，不能继续从旧索引召回。
- 核心人格与关系边界需用户批准修改。普通归纳不能写入具有更高指令优先级的人设文件。
- 凭证明文不进入普通账本、索引、摘要、上下文和诊断日志；受保护原件的回取/导出走单独授权，不能由“默认共享”或关闭脱敏直接获得。
- 锁定时的加密写入与解密读取分别控制；加密不可用时不退回明文，不能返回完整保存成功。

## 输入输出与失败行为

| 操作 | 输入 | 输出 | 关键异常 |
|---|---|---|---|
| 记录消息 | 主体、会话、角色、来源、幂等键、原文、接收时间 | 消息 ID 与持久化状态 | 磁盘满、重复键内容不符、数据库忙、非法编码 |
| 标记重要 | 消息/片段引用、标签、适用范围 | 重要记忆 ID、原文与版本 | 来源不存在、片段不匹配、预算超限 |
| 召回 | 问题、会话上下文、主体、可选日期/历史时点、预算 | 来源文本、事实状态、时间、命中原因、降级状态 | 模型超时、索引未完成、无证据、时间歧义 |
| 更正/撤销 | 目标版本、变更原因、新来源 | 新版本及替代关系 | 并发版本冲突、主体不明、证据不足 |
| 导出/恢复 | 快照或导出包、格式版本 | 完整性报告与恢复状态 | 不兼容版本、缺附件、哈希不匹配 |
| 保存受保护原件 | 来源、敏感标记、原件、幂等键 | 受保护对象引用、脱敏投影与持久化状态 | 加密未就绪、密文写入失败、两步提交中断 |
| 申请凭证明文 | 指定条目/版本、调用端、操作、用途 | 本地授权请求；批准后有限交付 | 口令错误、拒绝/超时、授权重放、对象版本变化 |

这些是契约需求，不是已发布 API。首版不提供完整桌宠 UI、多用户 SaaS、知识图谱、自动执行任务或公网服务。

## 尚待确认

- 首个 dsh 适配器的可靠采集/注入契约，以及后续 pi 和具体桌宠对象与接口。
- Python 建议方案的最终确认；目标操作系统、显存规格、磁盘与推理资源预算。
- 离线模型的具体选择；聊天和证据出机由调用端管理，服务不内置聊天模型。
- “最近一周”暂按滚动七天设计；是否需要自然周语义，以及默认时间区。
- 已明确显式记住与主动沉淀；仍需确定置顶交互与每轮必读集合的预算处理。
- 备份目的地、频率、加密方式、可接受丢失窗口和恢复时间。
- 拟议性能/准确率目标在真实机器与代表性测试集上的最终门槛。

这些待决项不阻碍研究与建仓，但在依赖它们的业务实现前必须确定。

## 本轮讨论的已确认语义

“忘记”默认不再召回且保留原始档案；“彻底删除”另行明确范围。普通召回新增等待约 1 秒以内作为待测目标，复杂追忆允许深入查询。详细分层、接入边界与决策树见 [design-session.md](design-session.md)，修订版整体设计已确认，技术选型仍需验证。

凭证策略以本轮加密保管选择替代早期“全部拦截”的假设，见 [credential-security.md](credential-security.md) 与 [ADR-0002](adr/0002-protected-credentials-outside-normal-recall.md)。具体保险库后端、主口令恢复与宿主采集覆盖在实现前验证。
